# T2 报告

状态：部分完成

工具实现、单元测试、样本实跑和 5 个切点的识图抽查已完成；漏切与误切各不超过 5% 的人工验收尚未完成，当前候选镜头包含疑似误切，不能作为已通过质量验收的结果。

## 完成内容

1. 镜头检测使用 PySceneDetect，支持 ContentDetector 和 AdaptiveDetector、可配置阈值。默认 ContentDetector 阈值 27；检测器先保留短切点，再把不足 0.3 秒的镜头并入较短邻段，等长时并入前段。视频开头、末尾及整集无切点均有处理。
2. 镜头首（起点后 0.1 秒）、中、尾（终点前 0.1 秒）优先取帧，默认按 2 帧/秒补帧、每镜头最多 12 帧；时间差不足 0.2 秒的帧去重，超过上限时均匀保留补帧。时间定位统一到 0.1 秒，图片长边为 960 像素。
3. 加密取帧生成时间区间目录、带时间码的 JPG 和同目录 `帧.json`。允许使用镜头表舍入后的全片终点，只提取真实存在的帧。
4. 连续镜头均匀分为每段 6–10 镜头，记录邻段边界镜头。全片仅有 1–5 镜头时单独成段；11 镜头无法同时满足每段 6–10，按任务允许的尾段合并规则合为一段。其他数量可满足 6–10。
5. 提供共享时间接口 `s2s.timefmt.to_sec(str) -> float` 和 `fmt(sec) -> str`，十进制四舍五入，支持分钟进位及超过 59 分钟的时间码。

### 5 个切点的识图抽查

使用 `s2s.vision.ask`，运行器 `pi`、模型 `opencode-go/kimi-k3`，每次发送切点前后两帧；不读取或打印 `.env`。在 48 个切点中等距抽取第 1、13、25、36、48 个，5 次调用均成功。

1. **K001 → K002，00:03.0，原始 2.966667 秒**：模型判断“同一镜头：否”。依据是女孩背后视角切为侧面全景，构图与背景明显改变。
2. **K013 → K014，00:22.1**：模型判断“同一镜头：否”。依据是全身景别切为面部近景，机位及背景空间关系改变。
3. **K025 → K026，00:45.6，原始 45.566667 秒**：模型判断“同一镜头：是”。依据是老人持手机的视角、景别和构图一致，仅口型、手机屏幕及字幕变化；此处为疑似误切。
4. **K036 → K037，01:05.8**：模型判断“同一镜头：否”。依据是幼儿园门口的中全景切为人物近景。
5. **K048 → K049，01:28.9，原始 88.933333 秒**：模型判断“同一镜头：否”。依据是人物近景切为麻将桌面俯拍特写。

辅助观察：核对图中的 `K024 → K025（00:45.1）` 也疑似为同一机位内的屏幕与画面变化；`K005 → K006（00:05.5）`、`K010 → K011（00:13.0）` 位于明暗渐变附近，需要结合连续视频裁定。以上均不计作人工标注结果。

针对“固定阈值将镜头内变化当作切换”这一解释，另实测了 AdaptiveDetector 默认阈值 3：合并后 48 镜头，排除了 45.1 秒和 45.6 秒切点，但也改变其他位置的切点。尚无人工真值，不据此认定另一组参数整体更准确，也未替换样本产物。

### `prompts/00-数据约定.md` 可追加内容

#### 镜头表

`镜头表.json` 顶层为对象：

```json
{
  "集": 1,
  "视频": "videos/sample/E01.mp4",
  "时长": "01:30.3",
  "镜头": [
    {
      "id": "E01-K001",
      "起": "00:00.0",
      "止": "00:02.4",
      "帧": [
        {"文件": "K001_01.jpg", "时间": "00:00.1"},
        {"文件": "K001_02.jpg", "时间": "00:00.5"}
      ]
    }
  ]
}
```

`集` 为正整数，`视频` 为输入视频路径，`时长` 为本集时长。镜头按视频顺序编号，时间统一为 `MM:SS.s`。首镜头从 `00:00.0` 开始，末镜头结束时间等于时长，相邻镜头首尾相接。原始检测时间在写入时舍入到 0.1 秒。

`帧[].文件` 为相对于本集 `素材/frames/` 的文件名，格式 `K{至少三位镜头序号}_{至少两位帧序号}.jpg`；图片长边 960 像素。`帧[].时间` 为本集内的取帧时间。帧按时间升序排列，去掉小于 0.2 秒的相邻采样，默认每镜头最多 12 帧；短镜头受间距约束时可以少于首、中、尾三张。

#### 片段表

`片段表.json` 顶层为对象：

```json
{
  "集": 1,
  "片段": [
    {
      "id": "E01-P01",
      "镜头": ["E01-K001", "E01-K002"],
      "起": "00:00.0",
      "止": "00:12.3",
      "衔接前": null,
      "衔接后": "E01-K009"
    }
  ]
}
```

`镜头` 引用镜头表中的连续镜头，按原始顺序恰好覆盖一次。`起`、`止` 分别取本段首镜头开始时间和尾镜头结束时间。`衔接前` 为前一段最后一个镜头编号，首段填 `null`；`衔接后` 为后一段第一个镜头编号，末段填 `null`。衔接引用不追加到本段 `镜头` 列表。

每段通常 6–10 个镜头，尽量均匀；全片不足 6 个镜头时单独成段，恰好 11 个镜头时合为一段。

#### 加密帧索引

加密帧存放于 `素材/frames_dense/<起>-<止>/`，目录名中的冒号替换为短横线，例如 `00-11.0-00-12.0/`。帧名为 `t00-11.2.jpg`，同目录 `帧.json` 格式如下：

```json
{
  "视频": "videos/sample/E01.mp4",
  "起": "00:11.0",
  "止": "00:12.0",
  "帧率": 5,
  "帧": [
    {"文件": "t00-11.0.jpg", "时间": "00:11.0"},
    {"文件": "t00-11.2.jpg", "时间": "00:11.2"}
  ]
}
```

`文件` 相对于该时间区间目录，时间为本集内时间。加密帧不采用镜头取帧的 0.2 秒去重规则。

### `tools/README.md` 可追加内容

#### 镜头切分与取帧

```bash
uv run python tools/shots.py videos/sample/E01.mp4 剧目/样本剧/E01/
uv run python tools/shots.py videos/sample/E01.mp4 剧目/样本剧/E01/ --detector adaptive --threshold 3 --min-shot-seconds 0.3 --fps 2 --max-frames 12
```

生成本集 `镜头表.json` 与 `素材/frames/`。`--detector` 可选 `content`（默认，阈值 27）或 `adaptive`（默认阈值 3）；`--threshold` 覆盖对应检测阈值。`--min-shot-seconds` 默认 0.3，至少 0.1 秒。`--fps` 为补帧率，默认 2；`--max-frames` 默认 12，至少 3。首、中、尾优先，时间差小于 0.2 秒的帧去重，超过上限时均匀保留补帧。图片长边为 960 像素。

集号优先从输出目录名 `E01` 推断，其次从视频名推断；其他命名须传 `--episode 1`。标准输出为镜头数量、帧数和耗时的 JSON 摘要。

#### 定向加密取帧

```bash
uv run python tools/dense_frames.py videos/sample/E01.mp4 00:11.0 00:12.0 5 剧目/样本剧/E01/素材/frames_dense/
```

依次传入视频、起点、终点、帧率和输出根目录。工具自动建立 `00-11.0-00-12.0/` 时间区间子目录，生成带时间码的 JPG 和 `帧.json`。时间区间为左闭右开；时间码精度为 0.1 秒，帧率范围为 `(0, 10]`。使用镜头表舍入后的全片终点时，超出真实终点的部分不取帧。

#### 连续镜头分段

```bash
uv run python tools/segments.py 剧目/样本剧/E01/镜头表.json
```

输出同目录 `片段表.json`，通常每段 6–10 镜头，段间大小之差不超过 1。全片 1–5 个镜头只成一段；11 个镜头合为一段。`衔接前`、`衔接后` 引用邻段边界镜头，首尾为 `null`。

共享时间接口：

```python
from s2s.timefmt import fmt, to_sec

assert to_sec("01:23.4") == 83.4
assert fmt(83.4) == "01:23.4"
```
