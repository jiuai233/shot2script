# T3g 声纹接入流程与跨集声纹参考

T3d 做了 CAM++ 声纹聚类（`tools/diarize.py`），但没有接入流程；E01–E03 直接聚类分别得到 25、25、23 类，一集实际只有五六个人，类太碎。总工已同意：把声纹正式接进流程，用多种线索把碎类合起来，并做跨集声纹参考。

背景报告：`orchestrate/reports/T3d.md`、`T3f.md`、`T11b.md`；工具说明见 `tools/README.md`。

## 负责文件

- `tools/s2s/voiceprint/`（新建）、`tools/voiceprint.py`（新建）
- `tools/s2s/asr/crosscheck.py`、`tools/asr_cross.py`（只加声纹步骤，已有行为不变）

在 `tmp/T3g/<集>/` 的黑板副本上实验。配置、数据约定、提示词的改动写进报告，由编排者合并。

## 1. 接入交叉核对

`asr_cross.py` 合并两路后，按配置自动运行声纹聚类并写回 `声线`。配置建议（写进报告）：

```json
"diarize": {"enabled": true, "model": "campp", "threshold": 0.6, "constraints": ["grok", "lipsync", "max_speakers"]}
```

## 2. 约束聚类，把碎类合起来

在声纹相似度的基础上，加入三类约束，每类都可以单独开关，权重和阈值参数化：

- **Grok 说话人标签**：副路 Grok 的词级 `speaker`（原始响应在 `素材/asr_raw/`，交叉核对结果中有对齐关系）。同一 Grok 标签的句子倾向合并；Grok 只作为倾向，不作为硬约束，因为它已知会合并不同的人。
- **口型记录**：`剧目/样本剧/<集>/口型记录.json`（编排者正在按当前声音记录重算，文件出现后再用；还没有时先用其他两类约束，在报告中说明）。结论为 `画内` 的句子按 `轨迹组` 分组：同一轨迹组开口说的句子必须合并（must-link）；同一时刻两个不同轨迹组分别开口的句子不能合并（cannot-link）。
- **人数上限**：已知角色卡人数或人工给定上限时，类数不超过上限加 1（留一个给未知声音）。

输出每句的声线、置信度、合并依据（哪类约束起了作用），以及每一类的代表句。约束之间冲突时保留为不同类，并记录冲突。

## 3. 跨集声纹参考

- `tools/voiceprint.py 入库 <剧目目录> <集号>`：一集的说话人确认后（归属表中说话人为角色编号），按角色计算该集声纹中心（平均向量与句数），存到 `剧目/<剧名>/声纹/<角色编号>.json`（向量、来源集、句数、模型名和版本）。
- `tools/voiceprint.py 比对 <剧目目录> <集号>`：新一集的每个声线类，与声纹库中各角色比对，输出相似度最高的 3 个候选及相似度，写入 `<本集目录>/声纹候选.json`。
- 候选只作为参考提示，不自动认定人物。数据格式写进报告，由编排者合并到数据约定，并提供给角色卡 agent。
- 声纹向量属于生物特征数据：只保存在本机黑板目录，不进入提示词全文、日志和报告（报告里只写相似度数值）。

## 4. 评测

- **合成基准**：T3 的三音色合成音频；再用 Grok TTS 合成第二段音频（同样三个音色、不同台词），模拟“第二集”，测试跨集比对能否把三个音色对到正确的角色。注意：只在合成数据上调用 TTS，调用次数尽量少。
- **E01–E03**：报告约束前后的类数、每类句数；约束聚类后各类的代表句音频导出到 `tmp/T3g/<集>/声线试听/`。三集之间做跨集比对（以 E01 的聚类结果暂代“已确认角色”入库），报告 E02、E03 各类的最佳候选和相似度，供总工试听判断。
- 人工回听结果（`回听结果.json`）和 E01 标注目前都还没有；评测函数先写好，用夹具测试，真值到位后可直接运行。
