# T9b 角色卡单角色试跑

任务说明见 `docs/任务拆解.md` 的 T9 一节。本子任务试跑角色卡 agent（`prompts/03-角色卡.md`）的建立模式：第一次把声音、声纹、口型、动作记录汇总起来认人和归属对白。

## 负责文件

- `tools/s2s/dispatch/materials.py`（只加角色卡需要的新资料）及对应测试
- `tmp/T9b/` 下的全部文件
- `orchestrate/reports/T9b.md`

提示词修订以“改前 / 改后”写进报告，由编排者合并。不修改 `剧目/`。

## 准备

1. 复制 `剧目/样本剧/E01/` 到 `tmp/T9b/E01/`（帧目录可用符号链接）。这份黑板已按人声重新切句（22 句），有两路交叉核对、声纹聚类（`声纹聚类.json`）、口型记录（`口型记录.json`）。
2. 动作记录与临时人物：T9e 已在相同的新镜头表上跑过动作识别，结果在 `tmp/T9e/E01/派发结果/` 下（查看 `orchestrate/reports/T9e.md` 确认路径和格式）。把它合并成黑板格式的 `动作记录.json`、`临时人物.json` 放进副本，用 `tools/validate.py` 校验。
3. **派发资料**：`materials.py` 中角色卡的资料清单加上 `口型记录`、`声纹聚类`、`声纹候选`（存在时）。声纹库原始向量不得进入资料。更新 `prompts/README.md` 资料隔离表的建议写进报告。

## 试跑

1. 用 `tools/dispatch_role.py 角色卡 --模式 建立` 在副本上派发。模型按配置默认。
2. **核对**：你自己逐句核对返回的对白归属和声音形态（画内、画外、心声、设备），依据是帧、口型记录、声纹聚类、对白称呼与语境。记录：
   - 说话人明显错归的句子（给出依据帧和理由）。
   - 声音形态判断错误（例如说话人不在画面却判为画内）。
   - 临时人物映射错误（不同人合并、同一人拆开）。
   - 描述名不可区分或用了泛称。
   - 依据写得空泛（“根据剧情”）或只靠弱依据就标“确认”。
   - 角色卡 agent 是否正确对待声纹：把同一声线当成同一人的证明、把跨集候选当成确认，都算问题。
3. 统计：归属确认句数、存疑句数、上述各类问题数、耗时、token 用量。
4. 针对问题修订提示词，保存为 `tmp/T9b/03-角色卡.修订.md`，用 `--提示词` 重跑一次，对比修订前后。

## 报告

逐句列出：句号、文本、返回的说话人与形态、你的判断、依据。最后给出修订前后对比表和合并建议。E01 人工标注尚未完成，你的核对不是人工真值，在报告中注明。
