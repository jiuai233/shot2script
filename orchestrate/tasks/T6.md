# T6 Word 生成与校验

任务说明见 `docs/任务拆解.md` 的 T6 一节。本任务单补充细节。

## 负责文件

- `tools/s2s/docx_build.py`、`tools/s2s/docx_check.py`
- `tools/docx_build.py`、`tools/docx_check.py`
- `tests/test_t6_*.py`、`tests/fixtures/t6/`
- `tmp/T6/`

## 输入格式

合并稿 Markdown 是各集正式稿按集号顺序拼接，集与集之间空一行。每集格式：

```
第1集
场景1-1：会议室，日，内
人物：林舟、沈宁、穿红衣服的小男孩
△ 林舟走到会议桌旁，拉开椅子，把文件放到桌上。
林舟（右掌拍在桌面上，抬高声音）：今天必须说清楚。
林舟（画外）：合同的最后一页还没有签字。
场景1-2：走廊，日，内（闪回）
人物：沈宁
△ 画面字幕：三年前
```

## 要求

### 生成

`tools/docx_build.py <合并稿.md> <输出.docx> <标题>`：

- 先解析范本 `simple/范本_TG26090377假穷真爱_剧本合集_20260916.docx`，在报告中列出范本中的样式、字体、字号、段距、页面设置和大纲级别，作为生成依据。
- 参考 `../v2t/tools/docx_flatopc.py` 的做法：以范本为底，复用其样式、主题和字体表，只重写正文。
- 首段为大标题（居中加粗），内容为 `<标题>`，例如 `TG26090377假穷真爱 剧本合集`。
- 集标题行设置大纲级别 1，场景行设置大纲级别 2，其他行为正文。字体和字号与范本一致，并在 run 上显式写出，不依赖主题字体回填。
- 每个集标题前空一段。

### 校验

`tools/docx_check.py <docx> <集数> [--缺失集 3,5]`：解析 Word 文件实际检查：

- 集标题按集号连续，`--缺失集` 中的集号不出现，其他集号不缺。
- 大纲级别 1 的数量等于集数，大纲级别 2 的数量等于场景行数量。
- 场景行格式 `场景{集号}-{序号}：地点，时间，内/外`，可选末尾“（闪回）”，序号在每集内连续；每个场景行下一段以 `人物：` 开头。
- 字体与字号符合范本。
- 文档结构完整，正文段落位于 body 内。
- 输出 JSON 结论，退出码 0 表示通过。

参考 `../v2t/tools/docx_verify.py` 的检查方法，场景行格式按本项目修改。

## 测试与实际运行

1. 以 `docs/视频逐镜头画声转写PRD.md` 2.3 节示例为基础，扩写成 3 集的合并稿夹具（含闪回场景、画面字幕、心声、电话台词），生成 Word，`docx_check` 通过。
2. 分别制造缺集、场景行格式错误、场景序号跳号、场景行后缺人物行，`docx_check` 报出对应问题。
3. 用 `textutil -convert txt` 或 python-docx 读回生成的 Word，正文内容与合并稿逐行一致。
4. 生成的 Word 文件放在 `tmp/T6/样例.docx`，报告中提醒总工用 Word 和 WPS 打开检查导航窗格。
