# T8 编排运行器

任务说明见 `docs/任务拆解.md` 的 T8 一节。本任务单补充细节。

## 架构

全剧主控和单集主控本身是 agent（提示词 `prompts/01-全剧主控.md`、`prompts/02-单集主控.md`），用开启工具的 pi 会话运行。它们通过本任务提供的命令行工具派发子 agent、校验结果、读写黑板。本任务做这些工具和启动入口，不把主控的判断逻辑写死在代码里。

模型一律通过 `tools/s2s/config.py` 的角色配置取得，不在代码里写模型名。opencode-go 只允许 `config/models.json` 中 `allowed_models` 列出的模型，运行器会拒绝其他模型。

## 负责文件

- `tools/s2s/dispatch/` 下的全部文件
- `tools/dispatch_role.py`、`tools/run_episode.py`、`tools/run_series.py`
- `tests/test_t8_*.py`、`tests/fixtures/t8/`
- `tmp/T8/`

## 要求

### 1. 先做能力探测

单个动作识别片段有 6 到 10 个镜头、每镜头最多 12 帧，图片数可能超过 `vision.max_images_per_call`（12）。探测两种方式，结果写进报告：

- **附件方式**：图片以 `@路径` 传入，单次最多多少张能稳定返回，耗时多少。
- **工具读取方式**：开启 pi 的 read 工具，提示词中只给图片路径，由 agent 自己读取需要的帧。确认识图模型能否通过工具读取图片并正确描述。

两种都用 `剧目/样本剧/E01/` 的第 1 个片段测。根据结果选定动作识别和验收的派发方式，写进报告。运行器需要新增参数（例如开启 read 工具但关闭写入工具）时，在 `tools/s2s/dispatch/` 内封装，不改 `tools/s2s/runners.py`；确实需要改时写进报告。

### 2. `dispatch_role.py`：派发一个子 agent

```
uv run python tools/dispatch_role.py <角色> --集 <本集目录> --变量 vars.json [--模式 ...] [--范围 ...] --输出 <结果.json>
```

- 读取 `prompts/` 下对应角色的提示词，替换 `{{...}}` 占位；没有被替换的占位报错。
- 按 `prompts/README.md` 的“派发时的资料隔离”表附上资料，只附该角色能拿到的文件；验收角色不得拿到动作记录、归属表。资料清单写成代码中的一张表，便于核对。
- 动作识别按片段派发：从片段表取本段镜头、衔接镜头，从声音记录取本段人声时间段（只给起止时间）。
- 调用 `s2s.agent.run(角色, ...)`；从返回中提取 JSON（成稿角色提取工作稿和对照表两部分）。
- 用 `s2s.validate` 校验返回内容；不合格时把错误附在提示词后要求重答，最多重答 2 次。
- 每次派发追加一行到 `<本集目录>/派发日志.jsonl`：时间、角色、模式、片段、输入文件、模型、耗时、重答次数、结果文件、成功与否；运行器能取得 token 用量时一并记录。

### 3. `run_episode.py`：启动单集主控

```
uv run python tools/run_episode.py <剧名> <集号> [--模式 完整转写|定向复核]
```

- 黑板不存在时调用 `board_init`。
- 用 `单集主控` 角色配置启动开启工具的 pi 会话，提示词为 `prompts/02-单集主控.md` 填好占位后的内容，附加一段工具说明：`dispatch_role.py`、`validate.py`、`coverage.py`、`lint_script.py`、`dense_frames.py`、`asr_window.py` 的用法。
- 断点续做：单集主控每完成一步更新 `状态.json` 的 `步骤` 字段；重新启动时把当前 `状态.json` 和已有文件清单附进提示词，让主控从未完成的步骤继续。已完成的片段识别结果存在时不重派。
- 会话文件保存在 `<本集目录>/会话/`。

### 4. `run_series.py`：启动全剧主控

```
uv run python tools/run_series.py <剧名> <集数>
```

同样方式启动全剧主控，附工具说明（`run_episode.py`、`docx_build.py`、`docx_check.py`、`validate.py`）。

### 5. 状态字段

`状态.json` 需要新增 `步骤` 字段（第 1 到 9 步的完成情况）。格式写进报告，由编排者合并到数据约定；`validate.py` 暂不认识该字段时，在报告中说明。

## 测试

- 单元测试用假的运行器（不调用模型）：占位替换与未替换报错、资料隔离（验收拿不到动作记录）、JSON 提取、校验失败重答、重答上限、派发日志、断点续做时跳过已完成片段。
- 实际运行：对 `剧目/样本剧/E01/` 的第 1 个片段派发一次动作识别，结果通过校验，写进报告（结果内容的质量由 T9 评估，这里只验证链路）。声音记录尚不存在时，人声时间段传空数组并在报告中说明。
