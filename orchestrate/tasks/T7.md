# T7 样本标注准备与评测脚本

任务说明见 `docs/任务拆解.md` 的 T7 一节。本任务单补充细节。当前只有一集样本 `videos/sample/E01.mp4`，先按一集完成，结构支持多集。

## 负责文件

- `eval/` 下的全部文件
- `tools/s2s/evaluate.py`、`tools/evaluate.py`
- `tools/annotate_sheet.py`（标注工作表生成）
- `tests/test_t7_*.py`、`tests/fixtures/t7/`
- `tmp/T7/`

## 要求

### 标注规范 `eval/标注规范.md`

写给人工标注者看，用大白话，带例子。覆盖：

- **台词**：逐字转写，起止时间精确到 0.1 秒，说话人用标注用人物表中的名称，形态（画内、画外、心声、设备）。
- **人物表**：每个人物一个标注编号，写外观和出现时间，姓名有依据才写。
- **关键动作**：按 PRD 6.1 的 5 类，写执行者、动作、对象、物件、结果、起止时间、类别。
- 判断不了的情况怎么标。

### 标注文件格式

`eval/样本/E01/标注.json`：

```json
{
  "集": 1,
  "视频": "videos/sample/E01.mp4",
  "人物": [{"id": "H01", "名称": "穿红花衬衫的白发奶奶", "外观": "……", "出现": ["00:05.0-00:30.0"]}],
  "台词": [{"id": "L001", "起": "00:03.2", "止": "00:05.1", "文本": "……", "说话人": "H01", "形态": "画内"}],
  "关键动作": [{"id": "M001", "起": "00:04.1", "止": "00:04.6", "执行者": "H01", "动作": "……", "对象": "……", "物件": null, "结果": "……", "类别": 4}]
}
```

用 JSON Schema 校验，Schema 放在 `eval/标注.schema.json`。

### 预填

人工从零标注太慢，先预填，人只做校对：

1. 台词：用 `剧目/样本剧/E01/字幕记录.json`（编排者已生成）中的 `台词字幕` 预填台词文本和大致时间，说话人和形态留空。声音记录尚未生成（语音识别在等凭据），生成后也可以用来预填。
2. 人物和关键动作不预填，避免把模型判断当成标注答案。

### 标注工作表

`tools/annotate_sheet.py <本集目录> <标注.json> <输出.html>`：生成一个本地 HTML 页面，方便人工校对：

- 按时间列出镜头，每个镜头显示几张缩略帧（引用 `素材/frames/` 下的图片，相对路径）和该时间段内预填的台词。
- 页面上可以直接修改台词文本、填写说话人和形态，添加人物和关键动作。
- “导出”按钮下载符合 `标注.json` 格式的文件。
- 页面只用原生 HTML、CSS、JavaScript，不依赖外部资源，离线可用。

生成 `eval/样本/E01/标注工作表.html` 和预填的 `eval/样本/E01/标注.json`。

### 评测脚本

`tools/evaluate.py <标注.json> <本集目录> [--稿 正式稿.md]`：按 PRD 8.2 计算：

| 指标 | 计算 |
|---|---|
| 台词逐字一致率 | 标注台词与对照表对应的正文台词逐字一致的句数 ÷ 标注台词总数（去标点空格、统一全半角） |
| 说话人错归率 | 说话人与标注不一致的句数 ÷ 对白总句数；人物对应关系通过标注人物与角色卡人物的映射表 `eval/样本/E01/人物映射.json` 确定 |
| 关键动作漏写率 | 正文和动作记录都没有覆盖的标注关键动作 ÷ 标注关键动作总数；时间重叠且执行者一致才算覆盖 |
| 无据动作率 | 在标注中找不到对应的正文动作 ÷ 正文动作总数（需要人工复核的候选，输出清单） |
| 人物错配率 | 执行者或对象与标注不一致的动作 ÷ 已匹配的动作 |

- 输出 JSON：每项指标的分子、分母、比率，以及每个错误的位置和双方内容。
- 匹配规则（时间容差、文本相似度阈值）做成参数，默认值写进报告。

## 测试

- 用标注自身构造一套“完美”黑板（声音记录、动作记录、归属表、对照表、正式稿），各项指标为满分。
- 人为制造已知数量的错误（漏 2 句、改 1 个说话人、漏 1 个关键动作、加 1 个无据动作、换 1 个执行者），统计结果与制造数量一致。
- `annotate_sheet.py` 生成的 HTML 用无头浏览器或解析检查：镜头数、预填台词数与输入一致，导出功能的 JavaScript 能生成符合 Schema 的 JSON（可以把导出逻辑抽成可单独测试的函数，用 node 跑）。
