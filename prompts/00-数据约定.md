# 数据约定

各角色提示词共用的编号、黑板目录和数据格式。全剧主控和单集主控按本约定读写黑板，子 agent 按本约定返回结果。

## 1. 编号

| 对象 | 格式 | 范围 | 说明 |
|---|---|---|---|
| 角色 | `C001` | 全剧唯一 | 一经分配不复用；人物合并后保留被并入编号的指向记录 |
| 临时人物 | `E01-P03-T1` | 本集本段 | 动作识别遇到角色卡中没有的人物时使用，由角色卡 agent 映射到角色 |
| 声线标签 | `E01-V2` | 本集 | 语音识别输出的说话人标签加集号前缀，只在本集内有效 |
| 对白句 | `E01-S001` | 本集 | 按时间顺序编号 |
| 镜头 | `E01-K001` | 本集 | 按视频镜头顺序编号 |
| 片段 | `E01-P03` | 本集 | 动作识别的处理单位，由若干连续镜头组成，不等于场景 |
| 动作条目 | `E01-A0001` | 本集 | 由单集主控合并动作记录时统一编号 |
| 场景 | `场景1-3` | 本集 | 成稿时确定 |
| 问题 | `E01-Q001` | 本集 | 待核对事项与验收问题共用一个编号序列 |
| 角色变更申请 | `E03-R01` | 提出集 | 由单集主控提出，全剧主控审核 |

时间统一写作本集内的 `MM:SS.s`，例如 `01:23.4`。

## 2. 黑板目录

```
剧目/{剧名}/
  角色卡.json            全剧角色卡
  角色变更记录.md        跨集变更的申请、审核结论和受影响集
  全剧状态.json
  声纹/                  各角色声纹（本机生物特征数据，不进入提示词和日志）
  E01/
    素材/                视频、音频、帧图片（固定处理流程产出）
    镜头表.json          镜头号、起止时间、帧图片路径（固定处理流程产出）
    片段表.json          动作识别的片段划分（固定处理流程产出）
    声音记录.json        语音识别结果（固定处理流程产出）
    字幕记录.json        画面硬字幕识别结果（固定处理流程产出）
    动作记录.json        动作识别结果，单集主控合并
    临时人物.json        动作识别中出现的临时人物及其映射，单集主控合并
    口型记录.json        每句对白的口型证据（固定处理流程产出）
    声纹聚类.json        声线聚类结果与合并依据（固定处理流程产出）
    声纹候选.json        各声线与全剧声纹库的跨集候选（固定处理流程产出）
    归属表.json          对白句的说话人与声音形态，单集主控确认
    待核对.json
    工作稿.md
    对照表.json          剧本行与对白句、镜头的对应
    问题清单.json        验收问题与复核结果
    验收报告.md
    正式稿.md
    状态.json
  合并/
```

## 3. 写入权限

| 文件 | 写入者 |
|---|---|
| 角色卡.json 中已确认人物的姓名、合并、拆分 | 全剧主控 |
| 角色卡.json 中本集新增人物、已确认人物的本集资料 | 单集主控 |
| 本集目录下的内容文件 | 单集主控 |
| 素材、镜头表、声音记录、字幕记录 | 固定处理流程 |

子 agent 不直接写黑板，只把结果返回给派发它的主控。主控校验格式、编号和依据后再写入。

## 4. 数据格式

`角色卡.json`、`声音记录.json`、`字幕记录.json`、`动作记录.json`、`临时人物.json`、`归属表.json`、`待核对.json`、`问题清单.json`、`对照表.json` 的顶层为数组，元素使用下列对应条目格式；`镜头表.json`、`片段表.json`、`状态.json`、`全剧状态.json` 的顶层为对象。

### 4.1 角色卡条目

```json
{
  "id": "C001",
  "名称": "林舟",
  "名称类型": "姓名",
  "状态": "已确认",
  "别名称呼": ["林总", "阿舟"],
  "外观": [{"集": 1, "描述": "黑色西装，短发，左眉有痣", "参考帧": "E01/素材/frames/K003_02.jpg"}],
  "声线": [{"集": 1, "标签": "E01-V2", "特征": "男声，中低音，语速快", "依据": "E01-S004 至 E01-S009 口型与声音同步"}],
  "关系": [{"对象": "C002", "关系": "沈宁称其为林总，疑为上司", "依据": "E01-S012"}],
  "身份依据": ["E01 00:12.3 人物字卡“林舟 林氏集团总裁”"],
  "性格总结": [{"集": 1, "内容": "当众施压，说话直接", "事件依据": "场景1-1 拍桌要求当场签字"}],
  "首次出场": "E01-K003",
  "待核对": []
}
```

- `名称类型` 为 `姓名` 或 `描述名`。描述名示例：“穿红衣服的小男孩”。
- `状态` 为 `已确认` 或 `待确认`。稳定 ID 跨集、换装延续，统一名称不与别名交替；非法人物代词或泛称不得登记为合法名称。

### 4.2 声音记录

```json
{"id": "E01-S001", "起": "00:03.2", "止": "00:05.1", "文本": "今天必须说清楚。", "声线": "E01-V2", "听辨": "清楚"}
```

`听辨` 为 `清楚`、`重叠`、`听不清` 之一。

生产声音条目必须带 `核对` 字段：

```json
{"核对": {"状态": "单路识别", "原始文本": "今天必须说清楚。", "异常": [], "优先级": 3}}
```

- `状态` 为 `单路识别`、`待核对`、`人工确认`。单路不表示已核实，不生成“两路一致”。`异常` 为具体原因数组，例如截断、超长句、疑似漏段、词时间异常、多人重叠、声纹待定或口型冲突。
- `优先级` 1 至 3，1 最高：截断、疑似漏段、时间异常及重叠为 1，身份或听辨存疑为 2，无异常为 3。异常句及没有识别文本的人声区间均登记阻断待核对；无文本区间只记时间，不造台词和句号。
- 句界由本地人声检测、短时能量及 Qwen 真实词级时间决定，不参考字幕，不从句级时间摊分造词。人声段保存到 `素材/人声段.json`：`[{"起": 0.06, "止": 0.49}]`，单位为本集绝对秒数。
- 词落在人声检测之外时保留真实词时间并标时间异常，不凭单路推断 VAD 或 ASR 哪一个正确。一集首尾没有静音时标 `截断: true`，不补字。
- 未完成裁定的异常保持 `待核对`，不能凭模型自评写成人工确认。字幕可缺失，仅供回听参考，不自动补词、改词或触发另一服务。

人工回听导出 `回听结果.json`，含 `声音快照`、`声音摘要`、`字幕参考` 和 `结果`；结果项含 `句号`、`决定`、`最终文本`、`听辨`、`备注`。单路决定为 `原文`、`字幕`、`手改`、`删除`。只有人工操作后才能写 `人工确认` 及 `决定来源`。应用时比较句号、原文及起止摘要，声线变化单独报告。

旧双路记录和裁定只用于历史读取和迁移，不进入生产识别。旧决定 `主路`/`副路` 不自动变为新句的人工确认；拆句、合句、变界或文本变化后必须重新确认。迁移写入 `素材/回听/裁定迁移.json`；删除导致句号变化时输出 `素材/回听/句号对照.json`，下游按对照重建。

### 4.3 字幕记录

```json
{"起": "00:03.2", "止": "00:05.0", "文字": "今天必须说清楚", "类型": "台词字幕"}
```

`类型` 为 `台词字幕`、`人物字卡`、`地点字幕`、`时间字幕`、`画面文字` 之一。`时间字幕` 指“一小时前”“三年后”这类标示时间跳转的后期字幕；`画面文字` 指手机屏幕、招牌等拍进画面的文字，只作为核对依据，不写入剧本。可选字段：`框` 为 `{"x": 0.1, "y": 0.7, "width": 0.8, "height": 0.1}`，坐标归一化，原点在左上；`置信度` 为 0 至 1 的数值。

### 4.4 动作条目

```json
{
  "id": "E01-A0012",
  "镜头": "E01-K004",
  "起": "00:04.1",
  "止": "00:04.6",
  "执行者": "C001",
  "动作": "右掌拍在桌面上",
  "对象": "桌面",
  "物件": null,
  "结果": "桌上的水杯晃动",
  "关键": true,
  "关键类别": 4,
  "依据帧": ["K004_01.jpg", "K004_02.jpg", "K004_03.jpg"],
  "确定度": "确认",
  "说明": ""
}
```

- `执行者`、`对象` 填角色编号或临时人物编号；对象是物品时直接写物品。
- `关键类别` 对应 PRD 6.1 的 1 至 5 类，非关键动作填 `null`。
- `确定度` 为 `确认` 或 `存疑`。不及物动作无需造宾语；状态不冒充动态过程，动作时间与证据必须可回查。

`形态` 为 `画内`、`画外`、`心声`、`设备` 之一。

```json
  "原文": "△ 他把文件推给沈宁。",
  "类型": "人物指代与角色卡",

  "相关人物": ["C001", "C002"],

  "处理职责": "成稿",
  "状态": "待修正",
  "复核结果": null
}
```

- `来源` 为 `识别`、`归属`、`成稿`、`验收`、`跨集` 之一。
- `类型` 为 `具体动作`、`动作与对白关联`、`人物指代与角色卡`、`声音与画面归属`、`全文完整性与一致性`、`角色卡资料` 之一。
- `级别` 为 `阻断` 或 `规范`，划分见 PRD 9.3。
- `状态` 为 `待核对`、`待修正`、`已修正`、`待人工裁定`、`已裁定` 之一。

`类型` 为 `场景行`、`人物行`、`△`、`对白` 之一。

### 4.8 单集状态

```json
{
  "集": 1,
  "状态": "验收通过",
  "返修轮数": 1,
  "未决问题": [],
  "角色变更申请": [],
  "本集新增人物": ["C007"],
  "结尾衔接": "林舟拿着信封走出会议室，沈宁仍坐在桌前",
  "步骤": {"1": true, "2": true, "3": false, "4": false, "5": false, "6": false, "7": false, "8": false, "9": false}
}
```

`步骤` 的键为单集主控流程的步骤号，值为该步是否完成；结果写入黑板后再标记完成。第 8、9 步为二选一分支。

`状态` 为 `进行中`、`验收中`、`返修中`、`验收通过`、`待人工裁定` 之一。

### 4.9 镜头表

```json
{
  "集": 1,
  "视频": "videos/sample/E01.mp4",
  "时长": "01:30.3",
  "镜头": [
    {"id": "E01-K001", "起": "00:00.0", "止": "00:02.4",
     "帧": [{"文件": "K001_01.jpg", "时间": "00:00.1"}, {"文件": "K001_02.jpg", "时间": "00:00.5"}]}
  ]
}
```

- 首镜头从 `00:00.0` 开始，末镜头结束时间等于 `时长`，相邻镜头首尾相接。
- `帧[].文件` 相对于本集 `素材/frames/`，格式 `K{三位镜头序号}_{两位帧序号}.jpg`，长边 960 像素；帧按时间升序。

### 4.10 片段表

```json
{
  "集": 1,
  "片段": [
    {"id": "E01-P01", "镜头": ["E01-K001", "E01-K002"], "起": "00:00.0", "止": "00:12.3", "衔接前": null, "衔接后": "E01-K011"}
  ]
}
```

- `镜头` 为连续镜头，全部片段按顺序恰好覆盖镜头表一次。
- `衔接前` 为前一段最后一个镜头，`衔接后` 为后一段第一个镜头，首段、末段对应填 `null`。

### 4.11 加密帧索引

加密帧存放在 `素材/frames_dense/<起>-<止>/`，目录名中的冒号换成短横线，例如 `00-11.0-00-12.0/`。同目录 `帧.json`：

```json
{"视频": "videos/sample/E01.mp4", "起": "00:11.0", "止": "00:12.0", "帧率": 5,
 "帧": [{"文件": "t00-11.0.jpg", "时间": "00:11.0"}, {"文件": "t00-11.2.jpg", "时间": "00:11.2"}]}
```

### 4.12 临时人物

```json
{"id": "E01-P02-T1", "片段": "E01-P02", "外观": "白色长发，戴圆框眼镜，穿白大褂", "出现镜头": ["E01-K012", "E01-K013"], "映射": "C003", "映射依据": "外观与 C003 一致；K007 人物字卡"}
```

### 4.15 口型记录

```json
      "镜头": ["E01-K008", "E01-K009"],
      "结论": "画内",
      "轨迹": [

          "轨迹组": "G1",

          "依据帧": ["证据帧路径"],
```

        }

- `结论` 为 `画内`、`未开口`、`看不到`、`存疑`；轨迹 `状态` 为 `开口`、`未开口`、`看不到`、`存疑`。未开口只提供非画内候选，不能单独区分画外、心声、设备。
- 轨迹编号为镜头号追加 `-F{序号}`，镜头内唯一，不跨镜头延续。`轨迹组` 为跨镜头的粗略候选，无法分组可为 null，不等同角色编号。支持与反例均按句去重；另一轨迹组明确开口时，该句中可见但未开口的候选组计反例。
- 框使用原点左上的归一化坐标，为该句有效时段内检测框的中位值；依据帧保留实际路径。逐帧曲线时间为支持 12 fps 的扩展格式 `MM:SS.sss`，对白起止仍沿用声音记录时间格式。
- `复核` 为 null，或包含 `状态`、`依据帧`、`结果` 的对象；未调用时可包含 `原因`。复核不能覆盖代码结论。顶层可附输入版本、模型信息、统计与证据目录；句条目可附代表帧和代表时间秒。
- `evaluate(记录, 标注, 轨迹组到角色映射)` 在人工校对后统计画内性及说话人准确率与覆盖率。存疑、看不到、未匹配及无身份映射不得从总准确率分母中删除。画外、心声、设备合为非画内候选进行画内性评测。

口型记录可附以下检测、主动说话人与复用证据；句级四类结论和轨迹四类状态枚举保持不变。

- 顶层 `版本` 为 baseline、side、model、fused；`主动说话人模型` 为 null 或含名称、权重、设备、推理帧率、子进程耗时与峰值的对象，可附 `复用模型输出` 路径及 `分段计时`。顶层 `复用侧脸记录` 可记录规则证据来源。
- 轨迹可附 `规则分数`、`模型分数`、`模型曲线`、`检测来源`、`嘴部区域`。模型分数为句内有效25 fps说话类softmax数值的均值，缺测为null，不表示已人工校准的概率。模型曲线项为 `{"时间":"00:05.600","说话概率":0.75}`。
- `检测来源` 可含MediaPipe、YuNet局部唇点、YuNet嘴部像素；`嘴部区域` 为null或归一化 `[x,y,width,height]`。`评分依据` 可附规则分数、规则状态、模型有效帧、评分冲突和测量方式。融合默认0.35×规则分+0.65×模型分，两分差绝对值不小于0.55时标存疑，参数以记录为准。
- 无可靠唇点的像素分支，曲线 `张合比` 为null，另附 `嘴部像素变化`；有效仅表示像素区域可测。纯像素轨迹的轨迹组可为null，不自动推定身份。
- 复核可附 `画面结论`、`与代码一致`、`补帧索引`；顶层 `复核统计` 可含存疑句数、已复核、一致、不一致、无法比较、本次调用、复用已调用、本次耗时秒、累计耗时秒（字段名为 `耗时秒`）。未调用或无法解析不能计作一致。静帧比较不等同音画同步真值。

分阶段复用时，`统计` 可附 `复用前流程耗时秒`、`本次增量耗时秒`、`复用模型生成耗时秒`、`本次主进程峰值MiB`。此时 `耗时秒` 为所需串行阶段成本累加，`进程内存峰值MiB` 为所需主进程阶段峰值的最大值；不表示本次单进程完整重跑的测量。模型子进程内存单列。

### 4.16 声纹聚类与跨集候选

本集 `声纹聚类.json` 为对象，包含：

- `句列表`：句号、文本、起止、声线、相似度、置信度、合并依据、待定、疑似重叠及依据。生产 `合并依据` 取 voiceprint、lipsync 的数组；grok、max_speakers 仅供历史读取；置信度为类中心余弦相似度截断至0–1，未经概率校准。
- `类别`：各类声线、句数、聚类句数和最多三条代表句；`类间相似度矩阵` 与 `矩阵声线顺序` 对应。
- `约束`：参数、冲突、cannot-link句对、must-link数。无法兼容的硬约束不强制合并；生产不使用 Grok 标签，不从已有角色卡推导本集人数上限。
- `输入可用性`：口型是否有效、缺失或过期的原因。缺失的线索不视为已使用。

自动流程只更新非待定句的声线，其他声音记录字段不变。待定句保留旧声线，必须结合侧表解释；跨集比对排除待定句。口型记录必须匹配当前句号、文本及起止时间。

全剧 `声纹/<角色编号>.json` 保存本机生物特征，格式以 `声纹库.schema.json` 为准。包含角色编号、模型、版本、预处理、向量、句数、来源集；`来源` 按集保存句数及该集均值。同集重入库替换贡献，跨集按句数加权。仅归属确认的角色编号、清楚且有效的音频入库；文件权限0600、目录0700。向量及各集均值不进入提示词、日志或报告。

本集 `声纹候选.json` 的 `声音摘要` 绑定当前句号、原文、起止与声线；变化后须重新比对。角色卡资料中的有效口型按当前声线重算候选配对，不沿用旧声线标签。格式以 `声纹候选.schema.json` 为准：顶层包含集号、模型、版本、预处理、`仅供参考: true`、`声线`。每个声线条目包含标签、有效句数、最多三个候选，候选仅含角色编号与余弦相似度。少于三个库角色时不补造候选；没有有效输入或库为空时候选为空。候选不构成人物确认，不自动写入归属表。
