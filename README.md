# shot2script

把短剧视频按镜头转写成制作剧本：人物明确、动作具体、对白逐字准确、画面和声音归属正确，经独立验收后交付单集剧本、全剧合并稿和 Word 稿。

产品要求见 `docs/视频逐镜头画声转写PRD.md`，当前待办见 `TODO.md`。

## 流程

```
视频
 ├─ 固定处理流程（本机工具）
 │   镜头切分与取帧 · 本地 Qwen3-ASR 单路识别 · 按人声切句 · 声纹聚类 · 口型检测 · 字幕识别（仅参考）
 │
 ├─ 人工回听：截断、时间异常、疑似漏段、重叠或身份冲突的片段，在离线回听页上逐句裁定
 │
 └─ 角色 agent（按集）
     动作识别 → 角色卡（认人、对白归属）→ 成稿 → 独立验收 → 返修（最多 3 轮）→ 正式稿
                                                         └─ 解决不了的进入“待人工裁定”
全剧主控：逐集调度、审核跨集角色变更、合并、生成 Word 稿
```

## 目录

## 模型

| 用途 | 当前配置 |
|---|---|
| 语音识别 | 本地 Qwen3-ASR 0.6B，唯一语音转文字路线 |
| 人声检测 | 本地 FSMN-VAD |
| 声纹 | 本地 CAM++（sherpa-onnx） |
| 口型 | 本地 MediaPipe、YuNet、Light-ASD |
| 识图 | `deepseek/deepseek-flash`，思考级别 high。动作识别、角色卡建立两阶段和验收读图直连 DeepSeek 官方接口，授权帧一次送入并逐张标注；角色卡建立先合并人物，再按片段判断对白归属。验收复核只送改动场景及相邻场景的帧 |
| 角色 agent | 模型为 `deepseek/deepseek-flash`，思考级别 high；上述读图阶段直连，其余调用使用 pi。角色卡定向核对仍按白名单读帧 |

所有生产生成式调用只允许 `deepseek/deepseek-flash`，默认值、角色覆盖、环境变量和重答均在调用前校验，不回退其他模型。字幕只作人工参考。实现及离线/真实验收状态见 `TODO.md`，真实识别质量须单独验收。

## Issue #2：固定单集 E0

生产默认入口继续使用原Pi主控；最薄固定调度须显式选择`--调度 固定`，当前是尚未接通真实计价的E0实验入口：固定预处理 → 分段动作 → 确定合并/临时人物登记 → 两阶段角色卡 → 显式审核或延期审核 → 成稿＋结构化动作排布 → 机械检查 → 独立全文验收 → 正式门禁或待人工裁定。延期审核没有任何默认批准，N和问题保留；首版不自动返修、跨集、总结或增加UI。

两个离线合同可从同一CLI运行，视频和帧都是明确占位，远程调用0次：

```bash
uv run python tools/run_episode.py 离线测试 1 --调度 固定 --视频 tests/fixtures/fixed_episode/input.mp4 --离线夹具 tests/fixtures/fixed_episode/pass.json --运行目录 /tmp/s2s-e0-pass
uv run python tools/run_episode.py 离线测试 1 --调度 固定 --视频 tests/fixtures/fixed_episode/input.mp4 --离线夹具 tests/fixtures/fixed_episode/pending.json --运行目录 /tmp/s2s-e0-pending
```

通过夹具只得到“正式交付候选”的**离线影子终态**；实际状态仍为待人工裁定，不能生成正式稿。另一夹具保留未审核N、完整对白和待裁定问题。真实正式发布分支另外用显式测试验收夹具验证既有门禁，不把模拟审查改成真实。

固定入口的真实运行先用 `--调度 固定 --预检`。E0尚未实现可公开配置的真实计价/账单接入，属于代码接入缺项，因此在任何预处理或付费调用前明确阻断；**没有完成E1真实整集、内容质量、费用或180秒验收**。预设2美元警告、5美元停止只作为保护阈值，不是价格预测或已可执行的美元承诺。现有DeepSeek适配器已逐HTTP请求挂接预算，覆盖初答、格式重答和网络重试，缺失usage/金额保留null；Pi内部请求不可观测，不进入该预算路径。固定成稿和验收文本原本就是无工具纯生成，现复用同一DeepSeek直连；旧工具主控未迁移。

显式固定调度默认在 `剧目/剧名/隔离运行/版本散列/剧名/E01/` 保存结果，不覆盖原E01。显式 `--运行目录` 中已有未冻结资料会被拒绝。相同输入/代码/配置/提示词复用断点；变化须新目录。每阶段输入SHA、输出、起止/耗时、异常、发布事务以及每次请求的模型/图片数/原始usage分别落账。`--审核 路径.json` 尚不存在时停在apply前并给审核模板，由审核者填写后重跑；省略该参数仅延期审核，不确认新人。

原长Pi仍是生产默认入口，也可显式 `--调度 主控`；定向复核继续使用它；它不具备新的逐请求费用保护。`run_series.py`仍走旧全剧流程。本轮测试结果及已知基线失败见 [E0实施与验证记录](docs/issue2-E0-implementation.md)，不能只看通过数当作全量全绿。

## 开始使用

```bash
uv sync                                  # 主环境
cp .env.example .env                     # 填写 DEEPSEEK_API_KEY 及按需的本地路径与配置覆盖
uv run pytest -m "not live"              # 单元测试
```

本地语音识别和主动说话人检测使用独立环境，复建命令见 `tools/README.md`。模型文件下载到 `models/`，来源和校验值记录在各自的实测文档中。

## 开发方式

开发任务由编排者写成任务单，派给 pi 执行者：

```bash
orchestrate/dispatch.sh <任务编号> [补充说明]
```

执行者只改任务单列出的文件，完成后写报告；共享文件的改动由编排者合并。
