# shot2script · 单集音画融合 MVP

把一集短剧视频转写成可审阅的剧本：人物明确、动作具体、对白逐字准确、谁在说话归属正确，并附带问题清单。允许不影响理解的小错，只有误导剧情的问题判为不通过。

详细设计见 `docs/单集音画融合MVP实施计划.md`。

## 工作流程

```text
① 固定准备：检查输入、提取整集音轨、视频转 base64
                         │
              ┌──────────┴──────────┐
              ↓                     ↓
   ②A 语音支路（串行）         ②B 视频理解
   MiMo ASR 转写               MiMo Pro 看原视频、听原声，
   本地 Qwen3 强制对齐 → 词时间    服务端按每秒 2 帧采样
   本地 VAD 按 0.3 秒停顿切句      输出：人物、动作、
   本地字幕 OCR → 同音字校正       逐句说话人与画面人物、
              │                   声音表现与神态
              └──────────┬──────────┘
                         ↓ 两路都完成才继续
              ③ DeepSeek 融合写稿（纯文本）
                 统一人物 → 判断每句说话人 → 写剧本
                         ↓
              固定检查（程序）：台词逐字、顺序、行号、人名、括号长度
                         ↓
              ④ DeepSeek 文稿检查（只读文字，分阻断与规范两级）
                         ↓
              ⑤ 保存工作稿、人物归属、核对结果、运行记录
```

每集 4 次远程请求：MiMo ASR、MiMo Pro 视频理解、DeepSeek 融合写稿、DeepSeek 文稿检查。其余步骤都在本机完成，不产生费用。

| 阶段 | 模型或工具 | 职责 |
|---|---|---|
| 转写 | `mimo-v2.5-asr` | 整集音频转文字，`language=zh` |
| 对齐 | 本地 `qwen3-aligner-0.6b` | 给转写文本配上真实词时间 |
| 切句 | 本地 FSMN-VAD + `s2s.asr.single.segment` | 按人声和 0.3 秒停顿切句，单句不超过 6 秒 |
| 字幕校字 | 本地 macOS Vision OCR（`s2s.subtitles`）+ `pypinyin` | 用画面字幕校正转写里的同音错字 |
| 视频理解 | `mimo-v2.6-pro`，流式 | 看画面、听原声，记录人物、动作和每句话的声音归属 |
| 融合写稿 | `deepseek-flash`，思考 high，上限 32k，流式 | 统一人物、判断归属、写完整剧本 |
| 文稿检查 | `deepseek-flash`，思考 high，流式 | 以读者身份通读剧本，找读不通、归错人等问题 |

## 用了什么技术，解决什么问题

| 问题 | 做法 |
|---|---|
| 推理模型长时间不返回、推理吃光输出额度 | 所有生成请求都流式接收，推理和正文分开保存；60 秒没有新数据或总计 600 秒就停止；融合写稿用 DeepSeek，输出上限 32k |
| 模型数行号容易数错 | 模型只在行首写编号标记 `〔E01-S001〕`、`〔A001〕`，行号由程序按标记计算，再去掉标记 |
| 同一人物前后叫法不一 | 剧本里的人物一律写 `{{P001}}` 引用，由程序统一替换成登记名；对白原文不替换 |
| 台词必须逐字准确 | 程序校验每句原文按顺序只出现一次，正文与原句逐字相同；改字、漏句、乱序或凭空多出的对白都判阻断 |
| 转写同音错字（他/她、出生/出声、桂枝/桂芝） | 本地取帧做字幕 OCR，与转写去标点后按顺序比对；只有一到两个汉字的一对一替换、而且逐字同音时才按字幕改字。增删字、数字写法和其他差异都保留转写；每处改动列入问题清单，原转写保留可查 |
| 细切句方便捕捉换人，但同一人的一句话被拆成几行 | 切句保持 0.3 秒的细粒度；融合时同一人不间断连续说的相邻几句合成一行。程序校验合并行只含同一人、同一形态，正文等于原句按顺序直接相连 |
| 镜头拍 A、说话的是 B | 视频理解对每句话分开记录“说话人”和“画面人物”，说话人以声音为主线判断；融合先读懂台词逻辑（问谁答谁、称呼、处境、前后连贯），再用视频观察印证，两者冲突时登记待核对 |
| 电话戏分不清谁在哪一头 | 画面里拿着电话说话的一方，括号写“对着电话”；从听筒传出声音的一方，括号写“电话音” |
| 括号只写“电话”“语速急切”，太空泛 | 括号写这句话怎么说：具体语气加声音、神态，如“追问”“叮嘱”“含泪坚定”“哽咽应答”，12 字以内，超出列入问题 |
| 动作描写太少 | 视频理解逐个镜头记录每个人看得见的变化，包括听者的反应；融合把听者的明显反应写成 △，穿插在对应台词之间 |
| 正文出现待核对标记，影响阅读 | 正文只写采用的内容；拿不准的说话人写最可能的人物，并登记到问题清单，程序会清掉正文里残留的标记 |
| 审核太严，小错也判不通过 | 结论分三级：有阻断问题判“不通过”；只有规范问题或上游待核对判“通过（附问题清单）”；没有任何问题判“通过” |
| 提示词写法 | 正向说明好的结果是什么样并给例子，限制条款写得很少；规则要跨剧集都成立，示例不用样片人名 |
| 控制费用、避免重复扣费 | 不自动重试；每次请求都记录模型、参数、耗时、`finish_reason` 和 token 用量；运行记录里隐去密钥 |

## 使用

环境要求：

- macOS：字幕 OCR 调用系统 Vision 框架，首次运行用 `swiftc` 编译 `tools/ocr/vocr.swift`；
- `ffmpeg`；
- 本地对齐环境 `envs/local-asr` 和模型 `models/asr/qwen3-aligner-0.6b`，复建方法见 `tools/README.md` 的“本地语音识别环境”一节；
- 项目 `.env` 里填写 `MIMO_API_KEY` 和 `DEEPSEEK_API_KEY`。

```bash
uv sync
uv run python tools/run_mimo_mvp.py <视频.mp4> --输出 tmp/experiments/MiMo-MVP/<运行名>
uv run pytest tests/test_mimo_mvp.py      # 单元测试，不发远程请求
```

视频的 base64 编码须小于 50 MB；输出目录已存在时直接拒绝，不覆盖。

输出目录：

| 文件 | 内容 |
|---|---|
| `工作稿.md` | 渲染后的剧本 |
| `人物归属.json` | 人物表、逐句归属（含正文行号）、采用动作、未决问题 |
| `核对结果.json` | 结论、阻断问题、问题清单，每项注明来源 |
| `运行记录.json` | 各阶段起止和耗时、每次请求的参数与用量、流程状态与内容结论 |
| `阶段产物/` | 每次请求的输入、原始响应、推理、结果，以及对齐、VAD、切句、字幕记录、字幕校字 |

## 文件

| 路径 | 内容 |
|---|---|
| `tools/run_mimo_mvp.py` | 入口：流程编排、请求、固定检查、渲染、结论 |
| `tools/s2s/asr/align_text.py` | 在本地对齐环境中运行的指定文本强制对齐 |
| `tools/s2s/subtitles.py` | 本地字幕 OCR 与字幕记录合并 |
| `prompts/mvp/视频理解.md` | 视频理解提示词 |
| `prompts/mvp/融合写稿.md` | 融合写稿提示词 |
| `prompts/mvp/文稿检查.md` | 文稿检查提示词 |
| `tests/test_mimo_mvp.py` | 50 项单元测试 |
| `docs/单集音画融合MVP实施计划.md` | 设计与验证记录 |

仓库里的其他工具见 `tools/README.md`。不入库的本机数据：`videos/`、`models/`、`envs/`、`tmp/`、`.env`。

待解决：

1. **视频理解被内容审核拦截**：MiMo Pro 视频理解累计 8 次请求，4 次返回 `content_filter`；同一视频重发有时能过，E01、E02 两个整集都还没跑通，触发原因服务端没有说明。需要定重试规则或备用模型。
2. **镜头拍 A、说话的是 B，仍会归错**：d19c35 第一句应是电话另一端的人说的，视频理解认定为镜头里的牌友，融合也照此归属。这句已登记待核对，但只靠提示词约束压不住，需要换机制，比如逐句判断声音是现场人声还是从听筒传出。
3. **△ 与说话人括号内容重复**：听者反应写多以后，个别 △ 和紧接着的括号写了同一件事，或在 △ 里出现意图判断。
4. **服务端抽帧无法核实**：请求里指定每秒 2 帧，接口不返回实际帧数和分辨率。
5. **验证素材单一**：目前样片都来自同一部剧，还需要用另一部剧（多人对话、无字幕、画外音）检验规则会不会过拟合。
