# 视频逐镜头画声转写 PRD

版本：1.3
更新：2026-10-17

规范性补充见 [生产版PRD补充](生产版PRD补充.md)。本版同步生产路线、人物命名、动作排布与验收级别；补充中的细化规则同样适用。**本文规定目标要求，不代表运行时代码已实现或真实素材已验收通过；实施与测试状态见 `TODO.md`。**

## 1. 产品目标

用户上传短剧视频，系统按原视频的播放顺序，还原人物明确、动作具体、对白准确、上下文一致的制作剧本。交付重点是人物动作与实际台词，不是文学创作、剧情总结或摄影解说。

人物说话时的短动作优先与对应对白写在一起，例如“林舟（拍桌，提高音量）：今天必须说清楚。”。其他人物的反应、独立动作和需要展开的动作过程使用 △。动作、情绪、声音表现均须有素材依据。

### 1.1 核心质量要求

1. 台词忠实原声，顺序与视频一致，不补写、改写或漏写；识别存疑时保留问题，不用顺口的文字替代核实。
2. 动作采用大白话，写清谁做了什么、实际存在的对象及重要结果。不为凑主谓宾补造宾语。
3. 分清画面人物、动作执行者和说话人，禁止将听者反应写成说话人的动作。
4. 人物全文使用角色卡的统一姓名或具体描述名，非对白人物描述不得使用代词或含糊泛称。
5. 不添油加醋、不写心理推断、不用文学化修饰，不把镜头运动写成人物运动。
6. 正式稿须通过机械检查和独立素材验收；证据不足进入待核对，不能靠删除关键动作或猜测归属来过关。

### 1.2 生产路线

- 全剧主控、单集主控、角色卡、动作识别、成稿和验收的远程生成式调用统一使用 DeepSeek。当前目标接入标识为 `deepseek/deepseek-flash`；不允许 Sol、GLM、Grok 等隐式回退。
- 唯一语音转文字路线为本地 Qwen3-ASR；取消 Grok STT 和双路 ASR 交叉验证。保留本地人声检测、CAM++ 声纹及口型/主动说话人组件。
- 单路结果不能标为“两路一致”或凭模型自评标为“人工确认”；异常根据音频、时间、漏段、重叠、身份冲突及人工裁定记录。
- 默认模型、角色覆盖、环境变量和重试均须经过调用前白名单检查。历史试验代码与报告可保留，但不进入生产入口。
- 生产链路未完成迁移时显式报告未就绪，不悄悄运行旧双路方案。配置修改、非 live 测试、真实调用验收分开记录。

## 2. 剧本内容与阅读形式

### 2.1 基本结构

正式剧本包含集标题、场景、时间与内外景、出场人物、△ 描述、人物对白和必要的画外/心声/设备声音标记。

按视频实际播放顺序组织内容；镜头时间与剧本内容保留可回查的对应记录，但不把时间码、任务状态、推理过程和验收批注混入正式正文。同一地点的切镜头不自动生成新场景。

### 2.2 动作与台词的关系

- 先确认动作属于谁，再按时间确定动作与哪句对白直接关联，最后决定括号或 △，不能倒过来按排版分配人物。
- 属于说话人本人的、简短且直接关联该句的动作，在不改变时序的前提下，必须优先放入人物名后的括号。例如 `林舟（举手，情绪激动）：你给我站住！`；情绪必须有表情或声音依据。
- 不应写成 `△ 林舟举手。` 再接 `林舟（情绪激动）：你给我站住！`，除非独立呈现是保持真实时序所必需。
- 长动作、需要展开的多人互动、其他人物反应、独立动作及必要场景变化写 △。关键动作可以放括号，但不能因压缩而丢失参与者、过程或结果。
- 简短递物等交互能在说话人括号内完整表达时，不因涉及第二个人就机械拆分；涉及其他人物必须写明统一姓名或描述名。
- 同一动作只写一次，不在相邻 △ 和括号中重复。实际发生在对白之后的动作不能被搬到对白之前。
- 没有动作时直接写对白，不为固定“动作—台词”节奏制造动作。

### 2.3 表达示例

以下示例均以视频确实呈现对应动作、声音及先后关系为前提：

```text
第1集
场景1-1：会议室，日，内
人物：林舟、沈宁、穿红衣服的小男孩
△ 林舟走到会议桌旁，把文件放在桌上。
林舟（右手拍桌，提高音量）：今天必须说清楚。
△ 沈宁停下翻文件的动作，抬头看向林舟。
林舟（画外）：合同的最后一页还没有签字。
△ 穿红衣服的小男孩走到沈宁身旁，把信封递给沈宁。
沈宁（接过信封，低头查看）：原件在这里。
```

林舟的拍桌动作与林舟的对白关联；画面转向沈宁后，持续的声音仍归林舟，沈宁的反应不能放进林舟的括号。

### 2.4 场景划分

- 地点变化、同一地点时间不连续（日转夜、明显跳时）、进入或结束闪回时新建场景。
- 同地点、时间连续的正反打、特写、插入镜头不新建场景；技术切片边界不是场景边界。
- 格式为 `场景{集号}-{序号}：地点，时间，内/外`，本集从 1 连续编号。
- 人物行列出本场出现或出声的全部人物，使用统一姓名或具体描述名。
- 地点无法确认时用可见描述，如走廊、病房，不推测具体名称。

### 2.5 声音形态与特殊标记

| 情况 | 写法 | 判断依据 |
|---|---|---|
| 已确认的画内说话 | 林舟：…… 或 林舟（动作、声音表现）：…… | 声音身份及画内说话证据成立，不能仅凭人物出镜 |
| 说话人不在画面中或画面拍听者 | 林舟（画外）：…… | 声音身份已确认，当前画面不是说话人 |
| 人物内心话 | 林舟（心声）：…… | 有内心独白的实际声音和语境依据；看不到口型本身不能证明心声 |
| 电话、视频、广播等设备人声 | 林舟（电话）：…… | 有声音通过对应设备传出的依据 |
| 闪回 | 场景行末标“（闪回）”，返回现实另起场景 | 有实际回忆、插叙画面依据 |
| 人物字卡、地点字幕、时间字幕 | △ 画面字幕：…… | 按既有范围照录后期说明文字 |

手机屏幕、招牌、牌匾、纸张等其他画面文字不写入剧本；拿手机给人看、读信等可见动作仍按动作规则描写。

有口型的自言自语按普通对白；口型、身份或声音形态无法判断时登记待核对。标记与声音表现置于同一括号，标记在前，如 `林舟（画外，声音发颤）：……`。画外、心声和设备声音的括号不添加不可见动作；可见听者动作单独写 △。

## 3. 业务流程

### 3.1 素材准备与声音识别

- 接收视频并确认剧名、集号、时长、音视频可读性，建立可追踪任务。上传、处理、失败、待裁定及交付状态必须明确。
- 使用本地单路 Qwen3-ASR 获取对白与真实词级时间，保存原始响应；不得用句级起止摊分伪造词时间。
- 按人声停顿和识别文本的句末标点切句，对话换人处尽量分句；本地人声检测辅助切句和疑似漏段定位；保留声纹、口型等候选证据。一个句段内有换人或重叠时不能自动归给同一个人。
- 字幕可能不存在或有误，不进入自动改写对白的决策；可在人工回听页面作为参考。人物字卡按身份证据核对，不等于对白真值。
- 截断、异常句界、疑似漏段、听不清、重叠、身份不明等登记待核对；仅重新处理需要核对的范围，不自动回退第二服务。
- 保存音画时间对应和所有裁定来源；重新切句后刷新下游引用，旧裁定不得无条件套用到新句界。

### 3.2 角色建立与画面识别

按镜头顺序识别人物、动作、可见神态、姿势及人物与物件互动。先绑定画面人物临时 ID，再结合全剧角色卡、外观连续性、人物字卡、可靠称呼回应、口型及声纹候选核对正式身份。

动作先明确属于哪个画面人物；姓名尚未确认时保留可区分的描述名。不得因镜头切换更换说话人。角色卡输入必须实际包含有效证据；材料缺失、过期或冲突须明确登记。

### 3.3 成稿与验收

1. 先统一人物身份、确认对白归属和动作事件，再按时间组织动作及台词。
2. 成稿只组织已确认事实，不自行补人、补动作或改写对白。
3. 执行机械校验：名称、格式、编号、时间引用、对白及关键动作覆盖。
4. 独立验收按原始素材检查全文，问题按职责定向返修并保留修正记录。
5. 复核通过才交付正式稿；未解决问题按 9.5 处理，允许查看明确标识的草稿。
6. 多集完成后核对跨集身份和上下文一致性，再合并并检查 Word。

## 4. 职责、任务范围与共享资料

### 4.1 职责分工

| 职责 | 内容 |
|---|---|
| 全剧主控 | 逐集调度，审核跨集角色变更，组织合并、跨集核对及未决问题汇总 |
| 单集主控 | 管理本集状态和黑板，校验子结果，处理冲突，组织返修，确认交付状态 |
| 角色卡 agent | 提交人物映射、对白归属和角色资料建议；不写剧本、不直接改公共角色卡 |
| 动作识别 agent | 根据本段及必要衔接帧提取动作、参与者、过程、结果、时间及证据缺口 |
| 成稿 agent | 把已确认记录组织为剧本，不改变事实、人物身份或声音归属 |
| 验收 agent | 独立核对原始素材与全文，输出问题、依据及复核结论，不直接改正文 |

素材读取、切分、取帧、保存、机械校验和格式处理由固定工具承担。所有生成式角色使用同一 DeepSeek 生产路线，不增加第二路模型验证。

### 4.2 按集任务与跨集延续

生产角色按集或片段运行，不在一个长期会话中累积整部剧。全剧角色卡持久化保留，各集读取已确认身份和称呼，再增量补充。

动作识别使用当前片段及必要前后衔接，不反复读取整集材料。片段边界处不得遗漏、重复或换错人物；衔接画面仅用于承接判断，不冒充本段动作。

### 4.3 受控黑板

子 agent 只获取授权资料、返回结果与修改建议，不直接覆盖角色卡或其他任务结果。单集主控校验格式、编号和依据后写入本集内容及获准的角色增量。

新增本集人物和补充本集资料可由单集主控审核；合并/拆分人物、修改已确认姓名等跨集变更须交全剧主控。名称变化时通过对照表定位受影响正文，统一修改并重新复核；不能留下新旧名称混用。

资料不足或冲突时保留待确认，不把存疑变成确定。每个阶段记录完成状态与输入版本；输入变化后不得复用过期结果。工具调用成功不等于内容验收通过。

## 5. 角色卡与统一命名

### 5.1 角色卡内容

每个角色保存稳定 ID、一个统一显示名、已确认别名、外观与参考画面、各集声音候选与对应依据、关系及身份依据、待核对事项。原有的简短性格总结仅作为附属资料保存并附事件依据，不用于认人、分配对白或补动作。

声音标签仅在其识别范围内有效，不直接跨集认人。相似声纹不是同一人的充分证据；同人多声线须核对。跨集候选不得自动当作正式身份，已有角色数量也不能用来强行合并新人物。

### 5.2 姓名与描述名

- 已确认姓名时，人物行、说话人标签、△ 及非对白描述全部使用统一姓名。
- 无姓名时使用有依据、可区分的完整描述名，如“穿红衣服的小男孩”“戴圆框眼镜的白发医生”。
- 禁止以“他、她、他们、她们、男人、女人、小男孩、小女孩、对方、前者、后者、另一人”等代替具体人物；禁止把非法泛称登记进角色卡来绕过校验。
- 完整合法描述名中的“小男孩”等词不能机械误报。对白原文中的姓名、称呼和代词保持原文；字卡照录也不机械替换。
- 同一人物跨镜头、换装、淋雨及跨集保持稳定 ID；描述名与新画面矛盾时先审核改名，再同步受影响全文，不交替使用简称。

## 6. 具体动作与 △ 描写规范

### 6.1 动作细度

每个独立人物动作句写清主语、动作、实际存在的对象和必要的可见结果。`沈宁站起身`本身完整，不为满足形式强行补宾语。对白括号的主语由括号前说话人提供，无需重复姓名。

动作多时拆成短句；同一句主语明确未变化可省略重复主语，换行、换人或有歧义须重写统一名称。不用“阻拦”“争执”“发生冲突”等概括词替代实际过程。

关键动作包括物品交接/取走/丢弃、推拉打抱跪拦、进离场与明显位移、拍桌指向出示证据、摔碎倒地受伤撕毁等影响剧情事实或对白理解的行为。要保留参与者、对象、物件、过程和结果，不因排版压缩漏掉关键动作。

### 6.2 大白话与事实边界

只描述实际发生的动作、可见状态和有依据的声音表现。禁止心理推断、小说式抒情、夸张比喻和剧情总结。

动态动作必须有视频过程或连续画面证据。拿着手机不等于拿起手机，伸着手不等于刚刚举手。看不清左右或对象时不猜；重要证据缺口登记待核对，不用模糊描述或删除关键事件掩盖。

不按动作行/台词行比例添加或删除动作，不为文字流畅补表情、情绪或原因。

### 6.3 △ 的人物指代硬约束

执行者、承受者、交互对象及物品所属人均须明确对应角色卡中的姓名或完整描述名。该规则同样适用于括号内涉及的其他人物；对白正文和规定范围内的照录文字除外。

每条独立人物动作有明确主语；真实物件结果或必要场景变化可用物件/场景作主语，不为凑人名添造动作执行者。

### 6.4 台词括号中的动作

先确认动作人等于说话人，再核对与台词的时间关系，最后检查能否简短且完整表达。满足条件优先放括号，不仅禁止重复，也禁止把本应放括号的短动作无必要地拆成 △。

听者动作、独立长过程及需展开的交互使用 △；合并会改变真实时序时不合并。具体正反例见生产版 PRD 补充第 5 节。

### 6.5 △ 不写镜头语言

不写特写、近景、远景、俯拍、镜头推近/拉远/跟随/扫过、慢镜头、画面切到、白光一闪、淡入淡出等摄影剪辑说明；不以“画面中”“镜头前”等作叙述框架。

运镜或切镜头展示了新的动作、反应或对白，就按实际顺序组织“动作—台词—动作—台词”；这是事件顺序，不是强制模板。纯运镜或静止画面无新动作时不造 △；摄影机移动不能写成人物走动。闪回、跳时仍按场景与画面字卡规则处理。

### 6.6 去掉 AI 腔

禁止比喻拟人、抒情渲染、心理判断、评价总结及“眼中闪过一丝”“嘴角勾起一抹”“缓缓地”“下意识地”“若有所思”“意味深长”等套路修饰。

神态写可见表现，如皱眉、瞪着林舟、哭、笑、低头。情绪不是必填项；有依据时才写“情绪激动”等，不以情绪替代实际动作。

### 6.7 动作执行者不能错

每个动作有对应记录、时间和依据帧。成稿通过稳定角色 ID 使用统一名称，不换执行者、不补执行者、不把两人的动作合成一人的行为。

只拍到手、背影、侧影时，核对衣着、饰品和位置连续性；不能确认则保留可区分描述与待核对，不能按剧情猜身份。外观相近人物逐一核对。反应属于画面中的听者，不属于画外说话人。

## 7. 镜头、时间与声音归属

### 7.1 时间与镜头对应

每个动作和对白可定位至本集时间。按视频播放顺序呈现闪回和插叙，不改成故事时间顺序。

一条对白可跨镜头，一个镜头可多人说话，不能一镜头强配一个说话人。确需按事件或说话人拆分台词时，应保留原文顺序及可追溯子区间；当前结构无法承载时登记待核对，先补齐数据与验证，不伪造时间或重复台词。

### 7.2 防止张冠李戴

画面人物、动作人、声音人分别判断。镜头转向听者时持续对白保留原说话人，并按实际情况标画外。

人物出镜、字幕位置、静态张嘴、声纹相似或剧情合理性均不能单独证明对白归属。证据冲突须回到素材，无法确认时不得作为确定事实进入正式稿。

### 7.3 其他声音

与剧情相关且实际可辨的环境音、音效及配乐变化可简要记录，不喧宾夺主。无对白画面不补人声。声音表现须有音频依据，不凭静态图片推断撞击声、脚步声或配乐变化。

## 8. 画面输入与识别效果要求

### 8.1 输入要求

采样须覆盖关键动作前后过程，能区分姿势与动作。快速动作、短暂表情、交接物品、局部身体及说话人疑点应支持定向加密核对。输入不足时保留问题，不能以文字细节代替证据。

相邻片段不得漏写、重复或错配。采样数量与密度须用实际素材评测；读完全部帧只证明覆盖，不证明识别正确。

### 8.2 评测指标

| 指标 | 计算方式 |
|---|---|
| 台词逐字一致率 | 与人工校对台词逐字一致的句数 ÷ 人工校对总句数 |
| 说话人错归率 | 说话人标错的句数 ÷ 对白总句数 |
| 关键动作漏写率 | 未写出的关键动作数 ÷ 人工标注关键动作总数 |
| 无据动作率 | 素材不支持的动作数 ÷ 正文动作总数 |
| 人物错配率 | 执行者或对象写错的动作数 ÷ 正文动作总数 |

统计时同时报告漏句、待核对及未匹配条目，不通过删除困难片段降低错归率。动作语义匹配程序给出的候选须人工复核，不能把候选直接当真值。

另检查名称/代词违规、小动作错误拆分、文学化表达和时序错误。机械规则要求无违规；识别质量门槛由总工依据真实标注样本确定。路线或提示词变化后使用同一批样本复测，不复用旧双路成绩证明新单路质量。

## 9. 独立验收 agent

### 9.1 验收输入与覆盖范围

独立验收使用全文、角色卡、镜头/时间记录、声音记录及原始画面证据，不读取其他子 agent 的推理过程，也不以角色卡一致替代事实核验。

全文包括场景、人物行、△、对白与括号。可分段检查，但须覆盖全部正文及相邻衔接；不得抽样冒充全文通过。整集文本检查与逐片段画面审查分别记录覆盖范围。

同一 DeepSeek 的独立会话不是第二种模型验证，不能视为无误保证；机械约束和原素材核对不可省略。

### 9.2 审查内容

检查动作的执行者、对象、物件、过程、结果与依据；小动作是否该放括号；听者反应是否被错配；人物名是否全文统一；对白是否忠实、完整、按序；有无脑补、文学化、镜头语言、遗漏或重复。

双向检查：正文每个动作有依据，素材中的关键动作也进入正文。角色卡与原素材冲突时指出角色资料问题，不能要求全文跟随错误身份。

### 9.3 问题与返修

每条问题包含集号、场景/镜头/时间或行号、原文、类型、级别、人物、证据或明确缺口、修正要求与复核结果。

- **阻断**：台词遗漏/改写/顺序错误、说话人或人物错配、任何无据动作、关键动作遗漏、动作语义不完整；非对白人物代词/泛称/名称漂移；短动作错误拆分、听者或复杂动作错误入括号、重复动作、时序错误、文学化/镜头语言、脑补心理或无依据情绪。
- **规范**：仅不改变事实与上述硬规则的其他排版或格式问题；不得用“规范”降级前述阻断项。

沿用返回 Schema 的 `阻断` / `规范`，不新增 `P0` 枚举。两级均须修正并复核才通过。主控按职责控制返修，不能让成稿通过删词、删动作或换人掩盖事实问题。

### 9.4 验收通过标准

1. 全文文本和对应画面已完整审查，覆盖记录明确。
2. 动作完整、有依据、人物正确、时序正确，短动作与 △ 排布符合 2.2 和第 6 节。
3. 人物全文统一，无未解决的指代、泛称、文学化或镜头语言。
4. 无未解决的错归属、漏台词、改台词、关键动作遗漏、无据动作或事实矛盾。
5. 全部问题已修正并复核，最终验收版本与实际交付版本一致。

### 9.5 未决问题处理

每集返修最多 3 轮；每轮复查原问题和受影响上下文，检查修正后是否引入新问题。仍无法判定或素材不足时记“待人工裁定”，提供明确标识的草稿与未决清单，不标验收通过。

人工裁定后更新正文/角色卡，再复核相关位置及上下文。合并稿只收录通过验收的集，存在缺失或待裁定集时列明集号，不冒充完整全剧稿。

## 10. 交付内容

交付单集 Markdown、全剧合并稿与 Word、全剧角色卡、镜头/动作/声音对照记录、独立验收报告。待裁定集另交草稿与未决清单。

正式正文只保留剧本内容；角色分析、定位、任务过程和验收说明分别保存。

Word 按 `simple/范本_TG26090377假穷真爱_剧本合集_20260916.docx` 排版：首页标题为“{剧号剧名} 剧本合集”；集标题、场景行、正文用三级样式，导航为“集 → 场景”；对白、△、人物行用统一正文样式，字体字号页面以范本为准。交付前实际解析检查集号、场景、导航与字体，不能以生成成功代替检查。

上传到交付入口须显示任务进度、错误原因、可恢复阶段和待核对项，支持定位视频片段及局部重跑。命令行片段跑通不等于 Web 上传产品已完成。

## 11. 重点验收场景

| 场景 | 预期结果 |
|---|---|
| 举手等短动作直接伴随对白 | 动作和有依据的情绪合并进说话人括号，不无必要另写短 △ |
| 说话时拍桌、指向物件 | 保留动作与对象，不仅写情绪；能完整表达时允许用括号 |
| 画面拍听者，原人物持续说话 | 听者动作独立 △，原人物对白按实际标画外，不换人 |
| 多人递物、拉扯、打斗 | 参与者、物件、过程和结果完整，不用泛称或概括词替代 |
| 同场相似人物、未具名人物 | 使用可区分的统一描述名，完整名称不会被泛称检查误报 |
| 换装、淋雨、跨集出现 | 身份连续，描述名调整经审核并同步全文，不自动拆人 |
| △ 或括号有他/她/男人等 | 按阻断指出位置；对白内原有代词不误改 |
| 无新动作、纯运镜或静止画面 | 不补动作、不强制造 △，不把相机运动写成人物走动 |
| 局部手部、背影 | 有连续性证据才认人，否则保留可区分描述和待核对 |
| 声纹/口型冲突、句内换人或重叠 | 明确存疑，不因统一句号、单个声线或剧情合理就强行归属 |
| 心声与自言自语 | 有实际依据再区分，看不到嘴不直接当心声 |
| 闪回和时间跳跃 | 按视频播放顺序，场景标记符合规则 |
| 人物/地点/时间字卡 | 按既有范围照录，其他画面文字不加入剧本 |
| 同一对白跨镜头或被动作穿插 | 不漏不重、时序正确，必要拆分有可追溯子区间 |
| 验收发现人物、动作或台词错误 | 按职责定向返修，复查上下文和新错误，不只删除命中词 |
| 跨集身份合并或改名 | 全剧主控审核，再复核受影响已交付集 |
| 3 轮后仍有问题 | 待人工裁定，交草稿与未决清单，不生成正式通过结论 |
| 非 live 测试成功 | 仅报告结构、约束与模拟链路验证，不冒充真实模型内容验收 |
