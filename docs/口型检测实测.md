## 检测与评分

### 侧脸补检

1. 原帧先用 MediaPipe；YuNet 补充未被已有框覆盖的人脸，IoU 大于 0.25 时不重复添加。
2. 补检框扩展 40%，放大到 512×512 后重检唇点，再映射回原图。
3. 缺少可靠唇点时，用 YuNet 嘴角确定嘴部区域，计算嘴部像素变化并扣除上脸变化；`张合比` 为 null，像素变化另列。
4. 不同测量来源分别追踪；纯像素轨迹不自动合并人物身份。人脸框和关键点不证明嘴部无遮挡。

规则分沿用张合幅度、静音基线和有限偏移音画相关性。像素分支使用句内变化 P90、静音变化 P90、噪声下限 0.015、尺度 0.08。头动、光照和框抖动仍可能影响结果。

### 主动模型与融合

ASD 输入为原视频真实 25 fps 画面、插值和平滑后的检测框、112×112 灰度脸，以及 16 kHz 单声道 PCM 提取的 13 维 MFCC/100 Hz 特征。人脸按官方 cropScale=0.40 裁为 224×224，再取中心区域。轨迹不跨镜头，最长每 6 秒分块；未采用多时长集成。

双类 softmax 的说话类数值逐帧保存；句内模型分取对应时段均值，未经本项目概率校准。

```text
融合分 = 0.35 × 规则分 + 0.65 × 模型分
|规则分 - 模型分| >= 0.55 时标存疑
```

模型权重与冲突差可配置。模型有效帧少于 4 时不产生确定结论；规则判定看不到时保留可见性限制。其他情况沿用阈值 0.6、存疑带宽 0.08。

模型版和融合版复用同一侧脸记录的规则分、轨迹、取帧和代表帧；轨迹时间来自冻结证据的毫秒时间码。融合版进一步复用模型输出，输入清单和权重路径须匹配。

## 读取、裁剪与推理计时

### 少量真实轨迹

选取 E01-K006-F4、E01-K014-F1、E01-K045-F3，共 110 帧。各项单位为秒。

| 方式 | 读取 | 裁剪 | MFCC | 网络推理 | 进程内总耗时 |
|---|---:|---:|---:|---:|---:|
| 逐帧随机定位 | 2.744 | 0.058 | 0.005 | 0.225 | 3.086 |
| 顺序共享解码 | 0.411 | 0.027 | 0.002 | 0.135 | 0.597 |

随机定位版本读取约占总耗时 89%。顺序版本按原视频帧号汇总所有轨迹请求，每个所需原帧仅解码一次，同帧多人分别裁剪；中间帧通过 `grab` 顺序跳过，不缓存整集高清原图。两种方式的 110 帧时间戳与说话分数完全一致。裁剪与网络推理的计时波动未单独用于归因。

证据：`tmp/T11b/profile/{输入,优化前,优化后,计时汇总}.json`。

### 整集模型阶段

129 条具有有效检测样本的候选轨迹中，84 条完成推理，45 条因不足 0.2 秒或不足 3 个检测样本跳过；句内缺模型分仍按评分规则保留存疑或看不到。

- 顺序经过 2,555 个原视频帧，解码取得其中 1,929 个请求帧，生成 2,804 张轨迹裁剪图。
- 读取 0.706 秒、裁剪 0.709 秒、MFCC 0.056 秒、网络推理 3.442 秒。
- 子进程内部总耗时 4.970 秒；含子进程启动和导入 5.738 秒；模型版全部增量阶段 5.848 秒，低于 1,200 秒上限。
- ASD 子进程峰值 1,945.34 MiB；本次进程树采样峰值 1,997.48 MiB。

## 使用

```bash
uv run --with mediapipe python tools/lipsync.py \
  videos/sample/E01.mp4 tmp/T11 tmp/T11b/新的模型结果/口型记录.json \
  --variant model --reuse-source tmp/T11b/side/口型记录.json \
  --asd-timeout 1200
```

`--variant baseline|side|model|fused` 默认 baseline。`--reuse-source` 仅支持 side 源记录加 model/fused 评分，沿用源参数；`--asd-source` 可复用输入匹配的 `asd输出.json`。输出 JSON 和核对 HTML 须不存在。

```bash
uv run --with mediapipe python tools/lipsync.py \
  videos/sample/E01.mp4 tmp/T11 tmp/T11b/新的复核结果/口型记录.json \
  --复核 --review-source tmp/T11b/fused_resume/口型记录.json
```

复核使用 `s2s.vision.ask(images, prompt)` 默认配置；已有已复核结果可复用，短句证据不足时按原视频帧率补取句内帧。少于 4 帧记录未调用，调用失败立即停止。
