# Shot2Script 生产版 PRD 补充

版本：1.3（规范已保存，运行时改造状态见 TODO）
日期：2026-10-17
原补丁基线：`0acd99332eb9eb8dca786dc92f9f9a7cc512f06b`

本文是原《视频逐镜头画声转写 PRD》的规范性补充。生产模型、语音路线、人物指称、动作表达、动作与对白排布及验收级别以本补充为准；原文其他规定继续有效。文中的“必须”是产品验收要求，不表示对应代码已经实现或真实素材已经验收通过。

## 1. 产品目标与边界

用户上传短剧视频，系统按原视频的播放顺序还原制作剧本，提供可阅读的草稿和通过验收的正式稿，支持 Markdown / Word 交付。

核心交付不是文学创作、剧情总结或镜头解说，而是：**人物全文同名、动作完整具体、用大白话表达、对白忠实原声、动作和声音不张冠李戴。**

正常素材自动处理；缺少证据的片段允许进入待核对，不能为了出稿而猜测。草稿与正式稿必须区分；正式稿只代表通过规定的验收流程，不承诺任意输入的识别结果绝对无误。

## 2. 生产模型与语音路线

- 所有生产中的生成式模型调用，包括全剧主控、单集主控、人物关联、动作识别、成稿和独立验收，统一使用已配置的 DeepSeek 接入。
- 当前配置标识为 `deepseek/deepseek-flash`，接入 DeepSeek 官方接口。动作识别和验收的读图由派发器直接调用官方接口，本次授权帧随请求一次送入，每张前标注文件名、所属镜头和时间；动作识别的授权帧按整集时间轴每秒 1 帧从本地帧中挑选，没有落到取点的短镜头只送中间 1 帧，本地取帧密度不变，字幕识别等固定流程照常使用全部本地帧；动作识别默认每段 17 个镜头（软上限 20，按送出的帧计算本段不超过 40 帧、含衔接不超过 48 帧），有画面人物的镜头不少于 8 个且超过七成没有动作条目时判为疑似漏看并重答；复核只送改动场景及前后相邻场景的帧；角色卡经 pi 按白名单读帧；主控和成稿经 pi 调用同一模型。
- Sol、GLM、Grok 等不进入生产调用链，不作为失败后的隐式回退。历史试验与报告可以保留，但必须与生产入口隔离。
- 本地 Qwen3-ASR 保留为唯一语音转文字路线；取消 Grok STT 和双路 ASR 交叉核对。
- 本地人声检测、声纹聚类、口型及主动说话人检测可继续保留。这些是本地专用识别组件，不是第二路远程生成式模型。
- 单路识别产生的对白不能冒充“两路一致”或“人工确认”。异常依据应改为实际音频与时间异常、疑似漏段、多人重叠、声纹/口型冲突和人工判断。
- 字幕可缺失、可错误，只作人工参考或有出处的人物字卡资料，不作为自动改写对白的真值。
- 生产白名单应在实际调用前校验，覆盖默认配置、角色覆盖、环境变量及重试路径。不得仅修改默认模型名。

## 3. 人物全文口径统一

### 3.1 固定身份和显示名称

内部使用稳定角色 ID 关联画面人物、动作执行者、动作对象及说话人。对外使用角色卡登记的一个统一人名或具体描述名。

- 已确认姓名时使用统一人名，例如“林舟”。
- 姓名未确认时使用有画面依据、足以区分人物的描述名，例如“穿红衣服的小男孩”。
- 不得在正文交替使用“穿红衣服的小男孩”“红衣男孩”“小男孩”等不同写法。
- 换装不等于新人物；若描述名与新画面冲突，先核对身份并审核名称变更，再统一更新受影响正文，不随意拆分身份。
- 角色卡按集继承、增量补充、定向纠错，不是每个片段重新生成一套姓名。

### 3.2 禁止含糊人物指代

△、人物行、说话人标签及对白括号的动作描述中，不得以“他、她、他们、她们、男人、女人、小男孩、小女孩、对方、另一人、前者、后者”等替代明确人物。

“穿红衣服的小男孩”等完整、已登记且可区分的描述名允许使用，不能因为其中包含“小男孩”而机械误报。角色卡也不得把“男人”“她”等非法泛称登记成合法名称来绕过校验。

对白原文以及按既有规则照录的画面字卡不按上述规则改写。人物确实说了“她”，对白中就保留“她”。

## 4. 大白话动作表达

### 4.1 动作语义完整

每条独立的人物动作描述写清：**谁 + 做了什么 + 对谁或对什么做 + 必要的可见结果。**

- 正例：`△ 林舟把文件递给沈宁。`
- 正例：`△ 沈宁把手机放在桌上。`
- 正例：`△ 沈宁站起身。` —— 不及物动作没有宾语，不为凑主谓宾添加对象。
- 反例：`△ 男人把东西递给她。` —— 人物、物件含糊。
- 反例：`△ 发生争执。` —— 没有交代具体动作。

每个独立的 △ 人物动作句应有明确的人物主语。同一句中的连续动作，在主语已经明确且没有变化时可省略重复姓名；换行、换人或有歧义时必须重新写明人物。

对白括号的动作主语由括号前的统一说话人名称提供，例如 `林舟（举手）：等一下。`，不要求在括号内重复“林舟”，也不能用代词代替动作对象。

### 4.2 不写文绉绉的语言

使用短句和日常动词；不写比喻、抒情、渲染气氛、心理推断或套话，如“眼中闪过一丝”“空气仿佛凝固”“意味深长地”“下意识地”。

“情绪激动”只有在声音或表情有充分依据时才能使用，不是每句必填字段；能确定为“提高音量”“哭着说”时，可以采用更具体的表现。

### 4.3 不得添油加醋

动作、对象、物件、方向、先后顺序和结果都必须来自素材。不能为了主谓宾完整、文字好看或叙事连贯而补出不存在的内容。

静态“手里拿着手机”不能自动写成“拿起手机”；没有动作过程证据时保留实际可见状态。不得把运镜造成的相对位置变化写成人物走动。

不确定左右手时不能猜一侧；对象身份不确定时不能按剧情选择一个人物。影响关键事件理解的证据缺口登记待核对，不得靠模糊化或删掉关键动作来获得通过。

## 5. 小动作与 △ 的排布

### 5.1 说话人本人的短动作优先放对白括号

动作属于已确认的说话人、动作过程短、与该句对白直接关联，且合并不会改变发生顺序时，必须优先写入该人物的对白括号。

原视频确实呈现相应动作与声音表现时：

```text
错误：
△ 林舟举起右手。
林舟（情绪激动）：你给我站住！

正确：
林舟（举起右手，情绪激动）：你给我站住！
```

这里的问题不仅是重复，还包括本可放在括号中的短动作被不必要地拆成独立 △。

不要把确实发生在对白之后的动作搬到对白之前；合并会改变时序时，保留独立 △ 或写清有证据的先后关系。

### 5.2 以下动作保留独立 △

较长或需要展开的动作过程、多人交互、非当前说话人的反应、无对应对白的独立动作，以及需要单独交代过程和结果的关键事件，使用 △。

“关键”不等于一律必须拆成 △：例如说话时拍桌，若能在括号中完整交代，并有素材依据，可以保留在括号中。判定依据是动作是否完整、人物是否正确、时序是否准确，而不是只看字数或关键词。短促的递物等交互若能在说话人括号内明确全部参与者和过程，也按此完整性原则判断；不得仅因涉及第二个人就机械拆分。

同一个动作只写一次，不同时出现在相邻 △ 和对白括号中。

## 6. 运镜与切镜头还原为动作、对白的实际顺序

不写“镜头推近”“画面切向”“特写”等摄影说明。镜头展示了先后发生的动作和对白时，按事件顺序组织：

```text
△ 林舟把文件放在桌上。
林舟：签字。
△ 沈宁把文件推回林舟面前。
沈宁：我不同意。
```

这只是有相应素材时的排布示例，不是强制的“每镜头一个 △”或固定交替模板。

- 小动作符合第 5 节时仍放在对应对白括号里。
- 镜头只有静止状态或移动，没有新动作，不额外创造动作。
- 镜头转向听者而声音继续时，保留实际说话人；听者的动作独立写 △，不能移到说话人括号里。
- 一句对白跨镜头不等于出现新说话人，也不能重复台词。确需分开呈现时保留原文顺序及可追溯的子区间；当前数据结构无法可靠承载时先登记待核对，不伪造时间或角色。
- 闪回按视频的实际播放顺序和原场景规则处理，不擅自改成故事时间顺序。

## 7. 事实与身份的证据约束

动作事件保留执行者、对象、物件、时间、镜头/连续帧依据及确认状态。对白保留原文、时间、声音候选、最终角色关联、画内/画外等形态和依据。

画面人物、动作执行者、说话人分别判断，再关联。声纹相似、人物出现在画面中、静态张嘴、模型自报置信度或剧情合理性，均不能单独证明说话人身份。

角色卡使用就绪且有效的声纹聚类、跨集候选和口型记录。口型检测在后台运行，角色卡不等待其完成；口型记录未就绪、缺失或过期须显式报告，不以缺证据推导否定事实。换人说话、同时说话和画外音不能被一个长 ASR 句子的统一声线掩盖。

成稿只能组织已确认事实，不修改动作执行者、动作对象或对白归属；证据冲突交回对应识别职责处理。

## 8. 成稿与验收共用的阻断规则

以下均为 P0 产品要求；在当前返回 Schema 中使用现有级别 `阻断`，不新造 `P0` 枚举：

1. 非对白的人物代词、泛称、含糊指代或全文名称不一致。
2. 人物动作语义不完整、动作执行者/对象错误、说话人错误或画声归属错误。
3. 无据动作、关键动作遗漏、重复动作、脑补心理和与素材不符的情绪。
4. 该合并的说话人短动作被不必要地拆成 △，或不该合并的听者/复杂动作被塞进说话人括号。
5. 运镜被当成人物动作、动作与对白顺序错误，以及本规范禁止的文学化和镜头语言。

原规范中被划为“规范”的上述问题，按本补充提升为“阻断”。修正必须检查相邻上下文，不是删掉命中词就视为通过。

可机械确定的名称、格式、引用、对白文字覆盖错误由程序拦截；动作真实性、人物身份和合理的动作排布必须对照证据审查。词表通过不代表事实通过，DeepSeek 再审一遍也不构成绝对正确证明。

未解决的问题留在草稿/问题清单中，不能出具“全部已核实”的正式稿。没有证据也不能通过删掉关键事件来过关。

## 9. 验收样本与工程落地

至少覆盖：小动作加对白、听者反应加画外音、持续运镜、多人递物、换装人物、只有局部身体、换人说话/重叠语音、无字幕、无新动作的静止画面、对白内含代词等情况。

人工真值评测同时检查说话人错归、动作人物错配、无据动作、关键动作遗漏和台词忠实程度；不能只统计保留内容而隐去被删除的困难片段。另检查名称违规、小动作错误拆分、文学化表达和时序错误。

实施仍需分别完成并验证：生产调用白名单、单路语音及异常核对的数据链路、角色卡证据装配、硬规则校验、真实视频到正式稿的端到端试跑、上传与任务状态入口，以及 90 秒单集 3 分钟内得到首轮验收结论的时效。
