## D1 模型与运行配置

当前配置，全部通过 `config/models.json` 切换，可用环境变量临时覆盖：

| 用途 | 当前选择 | 切换方式 |
|---|---|---|
| 语音识别 | 本地 Qwen3-ASR 0.6B（`local` 后端）为主路，Grok（xAI `/v1/stt`）为副路做交叉核对；豆包作为备选后端 | `asr.provider`、`asr.cross_check`，环境变量 `S2S_ASR_PROVIDER` |
| 识图 | pi 调用 opencode-go 的 `deepseek-v4.1-flash`，`glm-5.3-flash` 作为少量对照 | `vision.runner`、`vision.model`，环境变量 `S2S_VISION_MODEL` |
| 角色 agent | pi，默认 `openai-codex/gpt-6.1-sol`，思考级别 high；需要看图的角色使用识图配置 | `agents.<角色>`，环境变量 `S2S_AGENT_MODEL` |

运行器支持 `pi` 和 `opencode` 两种，新增运行器只需实现同一个调用接口。

opencode-go 只允许 `deepseek-v4.1-flash`、`glm-5.3-flash`，以 `deepseek-v4.1-flash` 为主。允许列表写在 `config/models.json` 的 `allowed_models`，运行器调用前校验，列表外的模型直接报错。

## T1 项目骨架

**目标**：建立本项目的目录、环境、模型配置和可切换的调用接口。

**产出**：
- `tools/`、`剧目/`、`videos/`、`tests/`、`config/` 目录；`.gitignore` 排除 `videos/`、`剧目/*/E*/素材/`、`.env`、`__pycache__`、`.venv`。
- Python 环境用 uv 管理（`pyproject.toml`），预装后续任务需要的依赖。
- `.env.example`：各服务的密钥、地址和代理变量名。
- `config/models.json` 与读取模块 `tools/s2s/config.py`：按 D1 的结构，环境变量覆盖配置文件。
- `tools/s2s/asr/`：语音识别接口 `transcribe(音频, 起, 止) -> 句列表`，后端注册表，`grok`、`doubao` 两个后端的空壳。
- `tools/s2s/vision.py`：识图接口 `ask(图片列表, 提示词) -> 文本`，按配置调用 pi 或 opencode。
- `tools/s2s/agent.py`：角色 agent 调用接口 `run(角色, 提示词, 附件) -> 文本`，按配置选择运行器和模型。
- `tools/README.md`：每个工具的用途和用法。

**验收**：
- `uv run pytest` 可以运行。
- `vision.ask` 用一张帧图片实际调用成功；修改配置或环境变量后切换到另一个模型也调用成功。
- `agent.run` 实际调用默认模型成功。

## T2 镜头切分与取帧

**目标**：从单集视频产出镜头表和帧图片，并提供加密取帧接口。

**产出**：
- `tools/shots.py <视频> <本集目录>`：
  - 检测镜头切换，生成 `镜头表.json`（格式见 `prompts/00-数据约定.md`），镜头号 `E{集}-K{序号}`。
  - 每个镜头取帧：镜头首、中、尾各 1 帧，另按固定帧率补帧。帧率和每镜头最多帧数做成参数，默认 2 帧/秒、每镜头最多 12 帧。
  - 帧图片命名 `K{序号}_{帧序号}.jpg`，存到 `素材/frames/`，镜头表中记录每帧的时间。
- `tools/dense_frames.py <视频> <起> <止> <帧率> <输出目录>`：加密取帧，供动作识别定向复看使用。
- `tools/segments.py <镜头表>`：默认每段 6 镜头，软上限 8；本段帧预算 36，含前后衔接镜头预算 48，超预算沿镜头边界缩小。片段边界放在镜头切换处，输出片段表和每段的衔接镜头。

**验收**：
- 在 D2 样本上人工核对镜头切换：漏切和误切各不超过总镜头数的 5%，结果写进 `tests/` 的说明。
- 镜头时间首尾相接，覆盖整集，没有重叠和空隙。
- 有单元测试覆盖时间计算和片段划分。

**参考**：PySceneDetect 或 ffmpeg 场景检测。

## T3 声音识别

**目标**：实现可切换的语音识别后端，产出带时间和声线标签的声音记录，并提供定向回听接口。当前测试使用 Grok，豆包作为备选。

**先做能力探测**，Grok 与豆包各测一遍，结果写成 `docs/语音识别能力实测.md`：
- 能否返回句级起止时间，时间精度是多少（与人工打点对比）。
- 能否区分说话人并给出标签；同一人前后标签是否稳定。
- 多人重叠、背景音乐较响时的表现。
- 探测不满足要求的项，列出可选方案交总工决定。

**产出**：
- `tools/s2s/asr/` 下的 `grok`、`doubao` 后端实现，接口与 T1 一致。
- `tools/asr.py <视频> <本集目录>`：按配置选择后端，生成 `声音记录.json`，句号 `E{集}-S{序号}`，声线标签加集号前缀，`听辨` 字段标出重叠和听不清。
- `tools/asr_window.py <视频> <起> <止>`：对指定时间段重新识别，供回听核对使用。
- API 密钥从 `.env` 读取，不写进命令行参数、日志和输出文件。

**验收**：
- 样本 3 集的台词与人工校对稿比对，逐字一致率和句起止时间误差写进实测文档。
- 失败重试、超时和限流有处理，单集失败不影响其他集。

**参考**：`../v2t/tools/ark_asr.py`（方舟调用方式与已验证的参数）。

## T4 字幕识别

**目标**：识别画面硬字幕和画面文字，产出字幕记录，并与声音记录对照。

**产出**：
- `tools/subtitles.py <本集目录>`：对帧图片做文字识别，合并相邻帧中相同的文字，生成 `字幕记录.json`。按画面位置和样式区分 `台词字幕`、`人物字卡`、`地点字幕`、`时间字幕`、`画面文字`。
- `tools/sub_vs_asr.py <本集目录>`：按时间对照字幕和声音记录，输出用字不一致、断句不一致、只有一边有内容的清单，供单集主控回听核对。

**验收**：
- 样本上人工抽查 50 条字幕：文字正确率、类型分类正确率写进 `tests/` 的说明。
- 对照清单没有因为标点、空格差异产生的误报。

**参考**：`../v2t/tools/vocr.swift`（macOS 文字识别）、`../v2t/tools/dict_alignment.py`（台词对齐方法）。

## T5 黑板与机械校验

**目标**：提供黑板初始化和所有可以机械检查的项目，减少主控和验收 agent 的重复劳动。

**产出**：
- `tools/board_init.py <剧名> <集数>`：按 `prompts/00-数据约定.md` 建立黑板目录和空文件。
- `tools/validate.py <文件>`：按数据约定校验每类 JSON：字段齐全、取值在枚举内、编号格式正确且不重复、引用的编号存在。
- `tools/coverage.py <本集目录>`：
  - 声音记录中每个句号在对照表中出现且只出现一次，顺序与时间一致。
  - 动作记录中每个关键动作在对照表中有对应。
  - 正文台词与声音记录逐字一致（忽略标点）。
- `tools/lint_script.py <工作稿>`：
  - △ 行和括号中的人物代词、泛称、含糊指代（对白冒号后的台词正文不检查）。
  - 画外、心声、设备形态的括号中出现动作词。
  - 场景编号连续、场景行格式、每个场景后有人物行。
  - 正式稿中残留待核对标记、时间码、编号。
- 每个工具输出 JSON 结果，供主控读取。

**验收**：
- 每条检查规则都有正例和反例的单元测试。
- `lint_script.py` 对 PRD 2.3 的示例零报错；把示例中的“林舟”改成“他”后报出对应行。
- 台词正文中的“他”“对方”不被报出。

## T6 Word 生成与校验

**目标**：把合并稿生成为符合范本排版的 Word 稿，并实际解析检查。

**产出**：
- `tools/docx_build.py <合并稿.md> <输出.docx> <标题>`：按 `simple/范本_TG26090377假穷真爱_剧本合集_20260916.docx` 的样式生成。集标题、场景行、正文三级样式；集标题和场景行设置大纲级别，导航窗格可按“集 → 场景”跳转。
- `tools/docx_check.py <docx> <集数>`：解析 Word 文件，检查集号连续、集标题和场景行的大纲级别数量、场景行格式 `场景{集号}-{序号}：地点，时间，内/外`、每个场景行后跟人物行、字体与字号符合范本。

**验收**：
- 用 PRD 2.3 示例扩展出的 3 集合并稿生成 Word，用 Word 和 WPS 打开，导航窗格显示两级目录，`docx_check.py` 全部通过。
- 故意制造缺集、场景行格式错误，`docx_check.py` 能报出。

**参考**：`../v2t/tools/docx_flatopc.py`、`../v2t/tools/docx_verify.py`（场景行格式按本项目 PRD 修改）。

## T7 样本标注与评测脚本

**目标**：为 PRD 8.2 的指标建立人工标注样本和计算脚本。

**产出**：
- `eval/标注规范.md`：如何标注台词、说话人、关键动作（执行者、对象、物件、时间、类别）。
- `eval/样本/E{集}/标注.json`：D2 样本 3 集的人工标注。由人完成，agent 负责准备标注模板和预填（例如用声音识别结果预填台词，再由人校对）。
- `tools/evaluate.py <标注> <本集目录>`：计算台词逐字一致率、说话人错归率、关键动作漏写率、无据动作率、人物错配率，输出每集和合计结果，并列出每个错误的位置。

**验收**：用标注本身作为输入时，各项指标为满分；人为制造已知数量的错误后，脚本统计结果与制造的数量一致。

**参考**：`../v2t/simple/20261013/` 下的制作稿可以作为台词与人物的参照，但不能代替逐镜头的动作标注。

## T8 编排运行器

**目标**：按 D1 的决定，让全剧主控和单集主控能按提示词派发子 agent，并能中断后继续。

**产出**：
- 提示词装配：读取 `prompts/` 下的提示词，替换占位，按各角色“你会拿到的资料”附上对应文件；资料隔离按 `prompts/README.md` 执行。
- 结果回收：子 agent 的返回结果先过 `tools/validate.py`，格式不对的要求重答，最多 2 次。
- 断点续做：每步完成后更新 `状态.json`，重新启动时从未完成的步骤继续，已完成的片段不重跑。
- 运行日志：每次派发记录角色、输入文件、耗时、token 用量和结果文件。

**验收**：
- 在一集样本上运行到成稿后手动中断，重新启动后从验收步骤继续。
- 日志可以统计每个角色的耗时和 token 用量。

## T9 单角色试跑

**目标**：在样本上逐个角色试跑提示词，确认输出格式和质量，修订提示词与参数。

按角色拆成 4 个子任务，可以并行：

| 子任务 | 输入 | 检查重点 |
|---|---|---|
| T9a 动作识别 | 样本第 1 集的 2 个片段 | 关键动作漏写、无据动作（静态写成动态）、口型记录、临时人物外观是否可区分 |
| T9b 角色卡 | 样本第 1 集全部声音记录和 T9a 的人物信息 | 说话人错归、画外与心声判断、依据强弱是否按规则 |
| T9c 成稿 | 人工确认过的动作记录与归属表 | 括号与 △ 的分配、指代规范、对照表完整、自查项 |
| T9d 验收 | 人为植入 15 个已知问题的工作稿 | 检出率、误报数、级别判断、依据是否写到帧和句号 |

**产出**：
- 每个子任务一份试跑记录：输入、输出、与标注的对比、问题和对提示词的修订。
- 修订后的提示词。修订涉及 PRD 规则时，先列出来交总工确认。
- 片段大小、取帧密度的建议值和依据。

**验收**：
- 输出全部通过 `tools/validate.py`。
- T9d 对植入阻断类问题全部检出。

## T10 端到端试跑

**目标**：用全剧主控跑完样本 3 集，产出全部交付物，计算指标。

**步骤**：
1. 先跑 1 集，检查每一步的黑板文件和日志。
2. 再跑 3 集，检查跨集角色继承、跨集一致性检查和合并。
3. 生成 Word 稿并通过 `tools/docx_check.py`。
4. 用 `tools/evaluate.py` 计算指标。

**产出**：`docs/端到端试跑报告.md`：各集状态、返修轮数、问题统计、指标结果、每集耗时与 token 用量、发现的问题和改进建议。

**验收**：3 集全部为验收通过或待人工裁定（附未决清单）；指标结果交总工确定上线门槛（PRD 8.2）。
