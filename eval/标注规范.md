# 视频逐镜头标注规范

人工标注以原视频为准。字幕只作预填参考，台词必须回听，人物与动作必须回看确认。未完成校对的文件不能作为正式整集评测答案。

## 1. 开始校对

1. 在项目原目录打开 `eval/样本/E01/标注工作表.html`，播放原视频。页面引用本地视频和帧图片，不需要联网；单独复制 HTML 会使素材链接失效。
2. 登记人物，逐条回听台词、修正文字和时间，补上说话人与声音形态。
3. 连续播放关键动作前后过程，补齐关键动作。缩略帧只供定位，单张图片不能证明“拍下去”“递过去”等过程。
4. 完整检查后勾选“已完整回看、回听并校对，无待核对项”，导出 `标注.json`。有疑点时保持未勾选，也可以导出保存进度。
5. 继续标注时在工作表导入已保存的 JSON。页面修改不会自动保存，关闭页面前必须导出。

时间都是本集播放位置，使用 `MM:SS.s`，精确到 0.1 秒。例如第 1 分 23.4 秒写 `01:23.4`。预填时间来自抽帧字幕，可能偏早、偏晚或只有一帧；必须按声音重新打点。

## 2. 人物表

每个人物登记一个标注编号，如 `H01`、`H02`。同一人物跨镜头、换装后仍使用原编号。编号不要反复分配。

- **名称**：有清楚的人物字卡、明确称呼等证据才写姓名；否则写能区分人物的描述名，例如“穿红花衬衫的白发奶奶”。不凭剧情猜身份。
- **外观**：记录发型、衣服、配饰等能区分人物的特征，例如“白色短卷发，红底花衬衫，戴金色耳环”。
- **出现**：按可见画面填写时间段；多个时间段用逗号隔开，例如 `00:05.0-00:09.2，00:12.0-00:30.0`。
- **只出声的人物**：仍登记单独编号，名称用有依据的称呼；没有可见外观时写“仅声音，外观不可见”，出现填空数组。
- **待核对**：同人不同衣、同衣不同人判断不清时，记录时间和具体疑点，不强行合并。

台词和动作中的人物使用 `H01` 这类编号。工作表的说话人菜单同时显示编号与名称，编号始终对应人物表中的名称。

## 3. 台词

实际说了什么就写什么，包括重复、语气词、口误和原话中的人名、代词。不要润色，不用字幕改掉实际声音。例如声音说“我、我没拿”，即使字幕写“我没有拿”，仍记“我、我没拿”。

每次完整说话或自然停顿分一条，连续的一句话不因镜头切换拆开。预填中同一句重复出现时合并；字幕没出现但声音说了的话要补上。工作表支持新增、删除台词以及修改起止时间。

| 字段 | 填法 | 例子 |
|---|---|---|
| 编号 | 本集唯一，按播放顺序整理 | `L001` |
| 起、止 | 人声开始、结束的位置，精确到 0.1 秒 | `00:03.2`、`00:05.1` |
| 文本 | 听到的原话，可加标点 | `今天必须说清楚。` |
| 说话人 | 人物表中的编号 | `H01` |
| 形态 | 画内、画外、心声、设备四选一 | `画外` |

声音形态按下列标准区分：

1. **画内**：实际说话人能在画面中看到。人物在画面里不等于正在说话，仍需核对口型和声音。
2. **画外**：实际说话人不在画面中，或者镜头正拍听者。镜头切到另一个人，持续的声音不能跟着换人。
3. **心声**：没有说话口型，且内容与素材表现支持心理独白。有口型的自言自语记画内；只凭“听起来像心声”不能定。
4. **设备**：声音从电话、视频通话、广播等设备传出。

同一句跨越画内和画外时，可以按形态变化处拆分时间，但原话不得重复或遗漏。多人同时讲话分别记录，时间可以重叠。

## 4. 关键动作

关键动作是会改变剧情事实、人物关系或对白理解的动作。按 PRD 6.1 分成五类：

| 类别 | 什么算这一类 | 例子 |
|---|---|---|
| 1 | 物品交接、取走、丢弃、所属变化 | H01 把信封递给 H02，H02 接住信封 |
| 2 | 身体接触与冲突 | H01 拉住 H02 的右胳膊，H02 停下 |
| 3 | 进场、离场、明显移动位置 | H01 从门口走到桌旁 |
| 4 | 直接帮助理解对白的动作 | H01 右掌拍在桌面上，接着说“今天必须说清楚” |
| 5 | 造成可见结果的动作 | H01 把杯子摔在地上，杯子碎裂 |

每条记录填写以下信息：

- **执行者、动作**：谁具体做了什么，例如执行者 `H01`，动作“右掌拍在桌面上”。“生气”“争执”“决定离开”不够具体，也不能代替可见动作。
- **对象、物件**：对象是承受者或交互对象，人物填编号，物品写名称；物件是使用或交接的东西。例如递信封：对象 `H02`，物件“信封”。没有对象或物件时留空，JSON 中保存为 `null`。
- **结果**：只写能看见的结果，例如“杯子碎裂”“H02 接住信封”。没有可见结果时留空，不补心理活动。
- **起、止**：动作过程的开始与结束，精确到 0.1 秒。例如举手从 `00:04.1` 开始，手掌接触桌面到 `00:04.6` 结束。
- **类别**：从 1 到 5 选最能体现剧情作用的一类。一个完整动作记一次；确实先后发生的递出、接住、放下可分别记录。

完整示例：

```json
{"id":"M001","起":"00:04.1","止":"00:04.6","执行者":"H01","动作":"右掌拍在桌面上","对象":"桌面","物件":null,"结果":"桌上的水杯晃动","类别":4}
```

静止的手举着，不能直接标成“举起手”；画面里拿着信封，也不能直接标成“接过信封”。需要回看动作之前和之后的连续过程。

## 5. 判断不了时

1. 听不清的原话，在文本相应位置写 `【听不清】`，在“待核对”写明时间和疑点；不要凭字幕或剧情补齐。
2. 说话人或声音形态不确定时留空，分别保存为 `null`；在“待核对”写出候选与冲突，例如“00:12.3 镜头拍 H02，但像 H01 的声音”。
3. 动作执行者不确定时留空，在“待核对”写明；动作过程不清楚时记录可见事实与缺失过程，不把推测写成确认动作。
4. 姓名不明但人物可区分时使用描述名，仍可完成校对；人物身份、动作或台词仍不确定时不能勾选“校对完成”。

预填文件使用 `校对完成: false`。Schema 允许留空保存进度；导出同时检查编号唯一、人物引用存在、起止时间顺序。正式整集评测要求 `校对完成: true` 且没有空说话人、空形态、空执行者和待核对项。

## 6. 人物映射与评测

人工人物编号与角色卡编号独立。确认对应关系后，填写标注旁边的 `人物映射.json`：

```json
{"H01":"C001","H02":"C003"}
```

正式整集评测中，每个人工人物都需有映射，目标编号必须存在于本剧 `角色卡.json`。人物尚未对应时保留空映射，不猜编号。

已有标注中，已填写且无待核对的字段，可在明确范围、分母及排除项的前提下用于**已有标注子集评测**，不因全剧 `校对完成: false` 要求对全部机器句重新标注。子集结论不等于正式整集验收，不得据此把源校对状态改成 `true` 或声称全量标注已验收；整集质量仍须完整校对，以下正式评测要求不变。离线工具与口径见 `tools/README.md` 的“已有标注子集”节。

生成或重新生成工作表：

```bash
uv run python tools/annotate_sheet.py 剧目/样本剧/E01 eval/样本/E01/标注.json eval/样本/E01/标注工作表.html
```

标注 JSON 不存在时，从 `字幕记录.json` 的台词字幕预填；存在时保留已有人工内容。人物和动作不自动填入。

完成标注并具备完整黑板与正式稿后运行：

```bash
uv run python tools/evaluate.py eval/样本/E01/标注.json 剧目/样本剧/E01 --稿 正式稿.md
```

多集通过 `--追加 <标注.json> <本集目录>` 重复加入；输出包含各集及按分子、分母累加的合计。相对的 `--稿` 路径相对于各本集目录。`--人物映射` 可指定映射文件；多集不指定时分别读取各自标注旁的映射。

### 计算口径

- 台词去掉标点和空白、统一全半角后逐字比较。正文通过对照表取得时间，不用声音记录中的文字替换正文。默认时间容差 `0.3` 秒，台词相似度阈值 `0.55`；相似度仅用来配对，未逐字一致仍算错误。默认最多合并 `3` 条断句，仅拼接后逐字相同才合并，避免漏句牵连相邻句。
- 说话人以正文标签和人工人物映射比较；分母为正文通过对照表引用的对白句数，未映射的对白行按一句计，漏句只计入台词漏句。无匹配标注的新增对白、混合说话人的合并行列为待复核。
- 关键动作默认文本相似度阈值 `0.55`；短动作全文出现在描述中按相似度 `1` 处理。按文本分数优先、起点距离次优一对一配对。正文或动作记录任一覆盖即可；时间重叠或间隔不超过容差，且执行者一致才算覆盖。
- 无据动作是需要人工复核的候选：标注只含关键动作，合理的非关键动作也可能进入清单。正文缺少动作时间映射时也进入候选。动作以对照表动作引用计数；未引用记录的 △ 或含动作词的对白括号整体算一个候选。复杂动作链需要完整对照表才能逐动作评测。
- 人物错配在时间与动作文本已匹配的正文动作中比较执行者、对象；分母按本任务要求使用已匹配动作数。对象、物件、结果的完整语义及动作真实性仍需人工核对。空分母返回 `null`，不视为满分。

参数：`--time-tolerance`、`--text-threshold`、`--action-threshold`、`--max-span`。输出含每项分子、分母、比率、错误位置及两边内容；退出码 `0` 表示计算成功，不表示质量验收通过。
